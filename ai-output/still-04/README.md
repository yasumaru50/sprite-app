# still-04: 写真の下書き（`--mode photo`）と輪郭の線（`--outline`）

入力は `ai-input/photo01.jpg`（部屋・廊下。2448×3264）と `ai-input/photo02.jpg`（建物。3264×2448）。
PNG・JSON は `python -m apps.still` の出力そのもの（CLI。JPEG の読み方の違いで、ブラウザ版では少し違う結果になる。下の注意）。

| ファイル | 作り方 |
| --- | --- |
| still-04_<写真>_plain.png | 写真をそのまま横 320 に縮めて今風の減色をしただけ（`--mode modern --width 320`） |
| still-04_<写真>_weak.png | `--mode photo --smooth weak`（弱。桑原フィルタ 半径 2・1 回） |
| still-04_<写真>_medium.png | `--mode photo`（中。半径 4・2 回。既定） |
| still-04_<写真>_strong.png | `--mode photo --smooth strong`（強。半径 5・3 回） |
| still-04_<写真>_medium_outline.png | `--mode photo --outline`（中＋輪郭の線） |
| still-04_<写真>_outline_overlay.png | 上の結果に、線を引いたドットを水色で重ねたもの（2 倍） |

| 写真 | 結果 | 大きさ | 色数 | 孤立したドットを置き換えた数 | 線を引いたドット |
| --- | --- | --- | --- | --- | --- |
| photo01 | plain | 320×427 | 32 | - | - |
| photo01 | weak | 320×427 | 32 | 1,073 | - |
| photo01 | medium | 320×427 | 31 | 80 | - |
| photo01 | strong | 320×427 | 32 | 44 | - |
| photo01 | medium_outline | 320×427 | 31 | 80 | 1,889 |
| photo02 | plain | 320×240 | 32 | - | - |
| photo02 | weak | 320×240 | 31 | 349 | - |
| photo02 | medium | 320×240 | 31 | 54 | - |
| photo02 | strong | 320×240 | 31 | 40 | - |
| photo02 | medium_outline | 320×240 | 31 | 54 | 2,752 |

感想:
- plain は床のがれき・壁・木の葉がざらざらの点のまま。弱でも点はかなり残る（置き換え 1,073）。中・強では床のタイル・壁・空・木が色の塊になり、塗り直しの下絵として形が読みやすい
- 中・強で減色の色の選ばれ方が変わり、photo01 の壁が灰色から黄土色寄りになった。強さを決める途中では、床に青・サーモン色の塊が出る組み合わせもあった（半径 3・2 回など）。色の選び方は今風と同じで変えていない
- 輪郭の線は、窓枠・建物の角・家具の縁に付いて形がはっきりする。一方で木の葉・床のがれきの縁にも細かく付く（明るさの差 0.25 以上。0.2 では床に付きすぎた）
- photo02（建物）はどの強さでも自然。photo01（散らかった部屋）は細かい物が多く、中でも床のがれきは大まかな塊になる

注意: JPEG を画素に戻すライブラリが CLI（libjpeg-turbo 3）とブラウザ版（Pyodide の Pillow は IJG libjpeg 9.0）で違い、photo01 では画素の 43% が平均 0.39（最大 42）ずれる。
そのため JPEG の入力では CLI とブラウザ版の結果が少し違う（PNG にした入力ではバイト単位で同じ。処理の部分は同じ）。
