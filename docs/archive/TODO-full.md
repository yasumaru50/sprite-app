## 守るべき制約

- `retrocore/` は NumPy と Pillow だけに依存する（Pyodide で動かすため。PySide6・SciPy・OpenCV も不可）。`tests/test_retrocore_deps.py` が確かめる
- 既存の関数の挙動は変えない。新しい機能はすべてオプトインにし、既定の出力が変わらないことをテストで確かめる
- 新しいモジュールには pytest を付け、テスト画像はコードで合成する（`tests/synth_sprite.py`・`tests/synth_cg.py`）
- プリセット名・コード・UI 文言にソフトハウス名や作品名を使わない
- 他の人が作った画像やゲームの画面をリポジトリに入れない（比較画像は自分の AI 画像か合成画像から作る）

## retrocore の CG 変換の部分（Sprite App からは使っていない）

`retrocore/` には、Sprite App の `retrocore/sprite/` のほかに、古いパソコン風の CG 変換（減色・ディザ・パレット・スタイル変換・解析）の
モジュール（`pipeline.py`・`palette.py`・`dither.py`・`color.py`・`preprocess.py`・`postprocess.py`・`preview.py`・`screenshot.py`・
`analyzer.py`・`style.py`・`optimize.py`）が入っている。ブラウザ版の HTML は `retrocore/` の .py をすべて埋め込むので、これらも入っている
（ビルド番号を前のリポジトリと同じに保つため、中身は変えていない）。

- テストは合成画像だけで動かす（`tests/test_core.py` など。回帰テストは `tests/test_golden.py`、期待値は `tests/golden/`、入力は `tests/fixtures/` の合成画像）
- 意図して出力を変えたときだけ `python tools/make_golden.py` でゴールデンを作り直す
- `tools/analyze.py`・`tools/compare.py`・`tools/export_db.py` はこれらのテストが使う
