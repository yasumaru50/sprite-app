# Sprite App 設計メモ

今の設計と方針だけをまとめたもの。工程の中身と値を決めた理由は [how-it-works.md](how-it-works.md)、オプションと出力の形は [cli.md](cli.md)、
昔の検討（比べた案・試した結果・PR ごとの決め方）は [archive/sprite-app-plan-full.md](archive/sprite-app-plan-full.md) にある。
コードのコメントが指す節（「フェーズ 2 の方針」「動きの表（タイムライン）の設計」など）の名前はこのファイルでも同じにしている。

## 方針

- 絵心がなくてもドット絵とドット絵アニメーションを作れるアプリ。目標は省力化（利用者の判断や操作をできるだけ少なくする）
- 完成の定義はフェーズ 1〜4 まで（3D 入力は対象外）
- 処理は `retrocore/sprite/`。`retrocore` は NumPy と Pillow だけを使う（Pyodide で動かすため）
- 新しい機能はオプトインにし、既定の出力を変えない（前の出力とバイト単位で比べるテストで守る）
- **迷ったら何もしない・動かさない**。作れないときは理由と次に試せることを出す（黙って別の設定で作らない。成功したように見えてしまうため）

## 目指す見た目と入力

- 今のインディーゲーム風のドット絵のキャラクター（縦 30〜50 ドット程度）。平塗り（ディザなし）、少ない色、輪郭は塗りより暗い色（黒に限らない）
- 古いパソコンの CG 風の変換（16 色・ディザ・タイルパターン）は Sprite App では扱わない
- 入力（優先度順）: (1) **AI が描いた「ドット絵風の画像」**（ドット 1 個が約 20px、場所により 19〜22px。ぼかしの名残の似た色・半ドットのずれがある）、
  (2) 普通のイラスト（縮小。優先度は低い。縮小だけでは「8 ビットゲーム」の印象になった）、(3) ラフな手描き（フェーズ 3）。入力の種類は利用者が選ぶ

## フェーズ

### フェーズ 1：AI 画像 → スプライト

```
背景除去 → グリッド検出（ドット絵風の入力）または 縮小（普通のイラスト）
        → 単純化 → クリーンアップ → 縁取り → パレット統合
```

- 背景除去は元の大きさのまま、グリッド検出・縮小の前（縮小後だと白い服など背景とつながった所まで消えるため）
- グリッド検出はドットの大きさと境目を見つけて 1 マス 1 色に戻す。見つからないときは変換せずに理由と対処を知らせて止まる
- 単純化・クリーンアップ・縁取りは**新しい色を作らない**（縁取りの外側の輪郭だけは内側の色を暗くした色を足せる）。目・頬・ハイライトのような小さな部品は守る
- パレット統合: 使った色をパレットファイルに保存し（`--save-palette`）、次のキャラをその色だけで描く（`--palette`）。合わせるのは単純化の直後。新しい色は足さず、
  別の部品が同じ色になったとき・近い色が無いときは警告する。ゲームエンジンは未定（Unity か Godot）なので、外部のドット絵エディタでも読める形式（.hex・.gpl）
- 各工程の中身は [how-it-works.md](how-it-works.md)

### フェーズ 2：全自動モーション

呼吸・横揺れ・浮遊・弾む・うなずく・伸びのプリセットと、数の表で書く自分の動き。GIF とスプライトシートで書き出す。

#### フェーズ 2 の方針

- **動きは「変換が終わったスプライト」を材料にして作る**。変換の処理（`convert_sprite()` と各工程）には手を入れない。処理は `retrocore/sprite/motion/`
- **決まりごと**（`base.py` の `check_rules()` で全フレームを確かめる）
  - 新しい色を作らない。拡大・縮小・ぼかしで色を混ぜない。ドットを動かす・増やす（複製）・減らすだけ
  - 全フレームの大きさを同じにする。足元の位置（いちばん下の行の、不透明な範囲の中央）を動かさない
  - 輪郭が途切れない（色ごとのつながりの数・シルエットの縁のつながりの数が変わらない、縁に輪郭以外の色が出ない。横の位置・帯・四角ではオイラー数も）
  - **迷ったら動かさない**。作れない形なら動きを付けずに警告する（変換の結果はそのまま保存する。途中のフレームだけ抜いたシートは作らない）
- **足元が動く例外**（浮遊・弾む・表の `root`）: 足元が**縦に決まった量だけ**動き、横には動かず、フレームが元の絵を縦にずらした**だけ**のもの、を許す
  （`check_rules(..., shifts=...)`）。ほかの決まりは同じ。表の中で足元が動いてよいのは範囲を持たない `root` の列だけ
- **分ける高さ**は「出力の画像の下から何ドット目か」（1 = いちばん下の行。継ぎ目より下は動かないので、2 本目の継ぎ目でも同じ数が同じ所を指す）。
  足元（下から 12%、2 ドット以上）と絵より上の透明な行は指定できない。指定した高さの上下 2 ドットの中で作れなければ、**動かさずに警告し、近くで作れる高さを知らせる**
  （ほかの高さに勝手に移さない・自動の高さで作り直さない・決まりを緩めない）
- **はみ出す分は透明の行・列を足す**: 横は左右に同じ数（pivot は真ん中のまま）、伸ばす・上にずれる分は上、下にずれる分は下。足した数は JSON の `padding`
- 各プリセットの考え方:
  - **呼吸**: 体の上の部分が 1 ドット下がって戻る。各列から 1 ドットずつ選んだ横向きの継ぎ目を抜き、その上を下げる。1 ドットの線は抜かない
  - **横揺れ**: 足元は動かさず、列ごとに高さを変えられる分け目から上を左右に 1 ドットずつ揺らす。高さを変えるのは横に同じ色が 3 ドット以上続く所の中だけ
  - **浮遊**: キャラ全体を分けずに上下に動かす（足元が動く例外）。上下に同じだけ動く波
  - **弾む**: キャラ全体を地面から上にだけ動かす（1 フレームに 1 ドットずつ）。着地だけ長く表示する
  - **うなずく**: 首から上が下がって戻る。首は横幅のくびれで自動で探し、見つからなければ付けずに試せる高さを出す
  - **伸び**: 呼吸の逆。継ぎ目のドットを複製して上を上げる
  - **小さな部品を守る**（既定は切）: 目・頬など（同じ色の塊で縦 3 ドット以下・面積 24 ドット以下）の長さを変えない。縦 3 なのは ai04 の頬（縦 3・横 3）を守るため
- 新しい動きは、なるべく動きの表の列か、表を埋めるプリセットとして足す
- **プリセットの出力（PNG の画素・JSON のバイト・警告の言葉）は変えない**（`tests/test_sprite_timeline.py`・`tests/test_sprite_region.py` が前のハッシュと比べる）
- **出力**: 横 1 列に並べたスプライトシート（透明 PNG、拡大しない、すき間なし）と同じ名前の JSON（版 2）。Unity（Grid By Cell Size）と Godot（Hframes）で読みやすい素直な形。
  `pivot` は足元。表示時間はフレームごと。形は [cli.md](cli.md) の「シートの JSON」
- GIF は見せる用（シートと同じ絵・同じ時間。シートの JSON には GIF の設定を入れない）。動きを作らなかったときは GIF も書かない

##### 作らなかった理由の記録（skipped）

- **目的**: 動きを付けなかった理由・自動の工程が警告を出した所を、出力の JSON に残す（JSON だけで「どのフレームが、なぜ」「次に何を試すか」が分かるように）
- **新しい判定はしない**。今ある警告（表の問題 `Problem`・首が見つからない・パレットの警告・コマの切り分け・範囲を写さなかった）を写すだけ（`motion/report.py`）
- **どこに書くか**: 作れたシートの JSON のいちばん外の `skipped`（何もなければ `[]`）。動きを付けなかったときはシートを書かず、`<出力名>_<動き>_skipped.json`
  （`image` は `null`、`made: false`）。動きの表（`--write-motion-spec`）には書かない（次の入力に使うファイルなので結果を混ぜない）
- **1 件の形**（並びはこの順。無い項目は書かない）
  - `stage`: `motion` / `grid` / `cleanup` / `outline` / `palette` / `frames` / `same_as_first`（グリッド検出・クリーンアップ・縁取りには今は記録が出る警告が無い。足すときはこの名前）
  - `code`: 機械で読める短い名前（下の表）。動きの `code` は表の問題の決まりの名前（`rule`）と同じ（名前が 2 通りあると取り違えるため）
  - `message`: 人が読む説明（表の警告の文と同じ。プリセットでも埋めた表の警告の文）
  - 動きだけ: `frame`・`frames`（0 から）、`row`・`rows`（表と警告と同じ 1 から）、`track`、`region`、`value`・`values`、`rows_from_bottom`、`box`（帯・四角の端）、`pixels`（元の絵の [x, y]。32 個まで）
  - パレットだけ: `colors`・`dots`・`target`・`distance`
  - `suggestions`: 次に試せる候補（実際に作って確かめたものだけ）。プリセットは CLI の引数の名前（`{"breathe_split": 11}`）、表は `{"region": "upper", "at": 14}` か
    `{"region": "head", "edges": {"left": 5, "right": 34, "bottom": 21, "top": 44}}`
  - `result`: `held`（動かさずに元のまま）・`merged`（パレットの同じ色にまとめた）・`nearest`（いちばん近いパレットの色にした）

##### 動きの表（タイムライン）の設計

「どこを」「フレームごとにどう動かすか」を数の表（`.motion.json`）で書き、1 つの仕組み（`timeline.py`）でフレームを作る。プリセットは表を埋める関数。
書き方の詳しい一覧は [cli.md](cli.md) の「動きの表」。

###### 1. 表の形（設定ファイル。JSON）

```json
{
  "format": "sprite-motion",
  "version": 1,
  "name": "breathe",
  "loop": true,
  "regions": {"upper": {"type": "split", "at": "auto"}},
  "tracks": {
    "upper_y": {"type": "deform", "region": "upper", "axis": "y"},
    "upper_x": {"type": "move", "region": "upper", "axis": "x"},
    "root_y":  {"type": "root", "axis": "y"}
  },
  "frames": [{"ms": 500}, {"ms": 500, "upper_y": -1}]
}
```

- シートの JSON とは別のファイル（`"format": "sprite-motion"` で区別する）。`name` はシートのファイル名と JSON の `motion`（英数字と `_`・`-`）
- 表の**行はフレーム**、**列はトラック**。書いていないセルは 0。**補間は持たない**（各行がそのまま 1 フレーム。見れば動きが分かり、作る側も確かめる側も単純）
- トラックは**位置**（`move`）・**変形**（`deform`。− が縮める・+ が伸ばす）・**体全体のずれ**（`root`。範囲なし）の 3 つ。値は −2〜+2（`root` だけ ±3）
- 知らない種類・知らない範囲・範囲外の値は**エラー**（書き間違いなので止める。変換の前にまとめて）。トラックの種類を足しても今の表はそのまま読める（`version` は意味を変えるときだけ上げる）
- 作れない組み合わせ（まだエラー）: 1 つの範囲に同じ行で横の位置と縦の変形、1 つの行で 2 つの範囲、分け目の範囲に縦の位置、`aim`

###### 2. プリセットを表で書くと

| プリセット | 範囲 | 列 | 既定の行 |
| --- | --- | --- | --- |
| 呼吸 | `upper`（分け目、`at: "auto"`） | `upper_y` | 0, −1（各 500） |
| 横揺れ | `upper` | `upper_x` | 0, +1, 0, −1（各 300） |
| 浮遊 | なし | `root_y` | 0, −1, 0, +1（各 400） |
| 弾む | なし | `root_y` | 0, −1, −2, −1（300, 150, 150, 150） |
| うなずく | `upper`（`at` は見つけた首の高さの数） | `upper_y` | 0, −1（600, 200） |
| 伸び | `upper` | `upper_y` | 0, +1（各 500） |

表で書けないもの: まばたき・口パク（差し替え）、白く光る・点滅（色）、汗や「！」（重ね）、回る・傾く・向きを変える（作らない）

###### 3. 決まりの確かめ方

1 フレームは「**ポーズ**（その行の `move`・`deform` を当てる。足元は範囲に入らないので動かない）」→「**体全体のずれ**（`root_y` だけ縦にずらす）」の 2 段で作り、
ポーズは `check_rules()`（足元が同じ）、ずれは「ずらしただけ・足元がちょうど `root_y` だけ縦に動いた」で確かめる。同じ値のポーズは 1 回だけ作る。
全部の行を確かめてからまとめて警告する（行は 1 から。同じ問題は「2・3 行目」のようにまとめる）。1 行でも作れなければシートは書かない。

###### 帯・四角の範囲

- 範囲は分け目（`split`。分け目から上が全部動く）・帯（`band`。`bottom`〜`top` の行の間だけ）・四角（`rect`。`left`〜`right`・`bottom`〜`top` の中だけ）。
  帯・四角は**囲んだ中だけが動き、外は 1 ドットも動かない**（剣のように分け目をまたぐ物を動かさないため）
- 端は端の行・列を含む。高さは下から何ドット目か割合、横は左から何ドット目（1 から）か、透明を除いたキャラの幅に対する割合
- 範囲は足元を含められない（含めると作らずに警告し、使える下の端を添える）
- **境目で作れないときは作らずに警告する**（作らない寄り）: 動いた後ろから見えてくる所の色が分からない（`hidden`）、外の違う色のドットを隠す（`overlap`）、輪郭の輪が切れる（`euler`）。
  端を 1〜3 ドットずらして実際に作れた範囲を「近くで作れる範囲」として添える
- 1 つの表に範囲はいくつでも書けるが、1 つの行で動かせる範囲は 1 つ（`root` は範囲ではないので一緒に使える）

###### 7. CLI と画面で同じ表を使う流れ

- CLI は `--motion-spec`（読む）・`--write-motion-spec`（プリセットが埋めた表を書く）。画面は「表で編集」「表を読み込む」「表を保存」。中身は同じ仕組みで、出力はバイト単位で同じ
- **別のキャラで使うときの高さ**: `at` が数だと背の違うキャラでは別の場所になるので、保存するときに数か割合かを選べる（`--spec-height number|percent`、画面は保存の前の 2 つの丸いボタン。既定は数）
  - 割合の基準は「透明の部分を除いたキャラの高さ」で、キャラのいちばん下の行から数える。割合 p% → 下から何ドット目 = 下の透明の行の数 + 四捨五入（p / 100 × キャラの高さ）（1 より小さければ 1）。
    数 → 割合は小数 1 桁（同じキャラで読み直すと同じ数に戻ることを確かめ、戻らなければ桁を増やす）
  - 作れたときは、範囲に実際に使った高さと線（`"used"`）を表に書く（読むときは使わない）。`--motion-spec` のシートの JSON には `"regions_used"` を足す。
    同じ線で作りたいときは範囲に `"lines"` を書く（分け目だけ）
  - プリセットの `--motion` のシートの JSON には書かない（前の出力を変えないため）

###### 決めたこと

- 行の番号は画面と警告は 1 から、シートの JSON の `index` は 0 から（画面の表の見出しは「行（1 から）」）
- 弾むの既定は 0, −1, −2, −1、着地だけ 300・空中 150 ミリ秒
- うなずくは新しい仕組み（`aim`）を足さず、首を絵から探して `at` に数を書くプリセット（そのため自動の首の表はそのキャラ用の数になる）
- 伸ばす（+）の使ってよい所は縮めると同じ（縮めて伸ばすと元に戻る）。目・頬の長さは「小さな部品を守る」で選ぶ
- やらないこと: 回す・傾ける・曲げる・向きを変える（ドットが混ざるか形が崩れる）、絵を描く作業（外部のエディタで描いて読むだけ）、表の中での補間
- 色・差し替え・重ねのトラックを足すときの 1 フレームを作る順番: 差し替え → 変形・位置 → 重ね → 色 → 体全体のずれ。色トラックでは「新しい色を作らない」を「元の絵の色と、表に書いた使ってよい色」にする

##### コマを切り分けてそろえる

- 何コマも横に並んだ 1 枚の絵（歩き・走り）を、全部のコマを「1 つのキャラ」として変換し、同じグリッド・同じパレット・同じ大きさ・同じ足元にそろえて 1 枚のシートにする
  （コマごとに変換すると色・グリッド・位置がずれてちらつくため）。処理は `frames.py`。1 枚の絵の変換と既存の工程の関数は変えず、工程は `build_pipeline()` の物を使う
- 縦にも何段も並んだ絵は、背景だけの行で段に分けてから段ごとに列で分け、左から右・上の段から下の段の順の 1 本の動きにする（自動。迷ったら分けない。
  コマの数を入れたときは分けない）。1 段の絵の出力は変えない
- ドットの大きさは全部のコマで 1 つ、線の位置はコマごと（AI はコマを別々に描くので位置がコマごとにずれる）。形の似たコマだけ線の並びを共通にする
- 順番: 変換 → 1 コマ目と同じにする範囲（`same.py`、人が選んだときだけ）→ ちらつきを減らす（`steady.py`、`--steady on` のときだけ）→ 手の直し（`touchup.py`、最後）→ 体全体の上下・シート → 差し替え（`swap.py`、まばたき。`--swaps` のときだけ）
- **ちらつきの見える化は直さない**（人が直すときの目印）。自動で戻すのは小さな違いだけ（オプトイン）。大きな違い（頭の描き直し）は人が範囲を選ぶ
- 範囲を写す・ちらつきを戻すは、1 コマ目かそのコマのドットしか使わない（新しい色を作らない）。目・口は「1 コマ目とまったく同じ」か「そのコマのまま」のどちらか。穴・輪郭の途切れ・足元の動きを作らない
- 手の直しは元のコマ（`source_frame`）ごとのドットの差し替えの一覧。パレットに無い色は作らない。直しが無いときの出力は前とバイト単位で同じ
- 差し替え（まばたき・口パク）は、1 コマ目の上に描いた別の形と 1 コマ目の違うドット。種類（`type`）ごとに形の名前と並べ方を決める（`blink` の `closed`・`half`、`talk` の `open`・`half`）。
  口パクはふつうのシートに入れず、別の「しゃべりのシート」（`<動き>_talk`）にする。
  シートを組み立てた後に入れ、かかるフレームは時間で分ける（全体の時間は変えない）。1 枚の絵の動きにも同じ関数で入れる。差し替えが無いときの出力は前とバイト単位で同じ
- シートの名前は `<出力名>_<名前>_<幅>x<高さ>_<N>f.png`（Piskel の「Import as spritesheet」に入れる数が分かる）。1 枚の絵の動きのシートは名前を変えない（前の版とバイトで同じことを守るため）

##### 動きに名前を付けてまとめる（PR #11）

- 「つなげる」を広げ、ファイルの一覧の各行に動きの名前を付ける。同じ名前が続くファイルは 1 つの動き、離れて出てきたらエラー（並べ替えを促す）。
  1 つのファイルは 1 つの動きだけ（2 つの動きで使うのは今回は入れない）。処理は `anims.py`、設定のファイルは `.anims.json`（CLI の `--anims`。画面で保存できる）
- 変換は全部のファイルで 1 回（`join.prepare_files()`。パレットは 1 つ、グリッドはファイルごと）。そろえるのだけ動きごと（縦のそろえ方・上げ下げは動きごと、横は共通）。
  そのあと、そろえた基準（pivot の横）と下端（地面）が全部の動きで同じ所に来るように透明の列・行を足して 1 つのキャンバスにする（拡大・縮小しない・ドットを動かさない）。
  半ドットの基準は合わせられない（ずらすとドットが動く）ので、そのままにした
- 結果は 1 つの `FramesResult`（全部のファイルの全部のコマ。`anims` に動きごとの範囲）なので、手の直し（`--edits`・画面の「ドットを直す」）は今までの仕組みのまま使える。
  直しの一覧には、いつも置いた位置（`origin`）を書く（ほかの動きの大きさでキャンバスが変わるため）
- シートは 1 つの動き = 1 行（横はいちばんコマの多い動き、余りは透明）。Godot の SpriteFrames は行と列で分けて読み込めるので、行ごとに動きを分けた。
  JSON は今のコマのシートの形に `animations`（`frames` は通し番号・`duration_ms`・`loop`・`row`）を足しただけ（コマごとの `air` などは今までどおり）
- GIF と .piskel は動きごと（`<出力名>_<動き>`）。読み戻しも動きごとで、直す前のまとめたシートからほかの動きのコマを使う。どの動きかはファイルの名前から決め、分からなければ選ばせる
- まばたき・口パク・重ね・1 コマ目と同じにする範囲・ちらつきを減らす・ちらつきの見える化・体の上下（root_y）は、まとめている間は使えない
  （どれも「1 コマ目」「1 つの動き」を前提にしているため。画面では欄を隠して理由を出し、CLI は警告して無視する）
- 印を付けないときの出力は前とバイト単位で同じ（`join.py` は関数を分けただけ）

#### 重ね（漫画的エフェクト）

- 汗・「！」などは、動きの表のトラックではなく**キャラのシートとは別の小さなシート**（`retrocore/sprite/fx/`。PNG と JSON `"format": "sprite-fx"`）にした。
  キャラのシートを変えずにすみ（エフェクトを選ばないときの出力は前と同じ）、キャラとエフェクトが別の長さ・別の時間でよく、ゲームでは子のスプライトとして重ねられるため
- JSON の `position` はキャラのコマの左上から見たエフェクトのコマの左上（ドット）。決まりごとと置く場所の決め方は [how-it-works.md](how-it-works.md) の「重ね」
- 絵は文字の表（`fx/art.py`）。新しいエフェクトは `EFFECTS` に 1 つ足すだけ（画面と CLI の選択肢は自動で増える）

#### 手直しの読み戻し

自動の変換のあと、人が Piskel で直す前提（手順は [sprite-edit.md](sprite-edit.md)）。処理は `edit.py`（`readback()`。作るファイルを全部 `{名前: バイト}` で返すので、CLI と画面でバイト単位で同じ）と `piskel.py`。

- **直したドットはそのまま使う**。新しい色・半透明・同じコマの食い違いは、作って警告し、場所の画像を出す。直すのは利用者が選んだとき（`--fix-colors`・`--same-frames first`）だけ
- 作らないのは、シートとして読めない（大きさ・コマの数が合わない・透明だけのコマ）ときだけ
- 時間・順番・pivot・padding・offset_y・source_frame・source・skipped は元の JSON から引き継ぐ（Piskel はコマごとの時間を持たない）
- 同じコマを 2 回使う順番（1,2,3,2）でも、シートは**再生する順に 1 コマずつ**並べる（Piskel の再生・エンジンの読み込みがそのまま正しい動きになる）
- コマのシートの JSON に `palette`（使った色）を足した（PR #40 から。1 枚の絵の動きのシートの JSON は変えない）

## ブラウザ UI の方針

- **Pyodide で retrocore をそのまま動かす**（.py を変えずに読み込む）。サーバー側の処理はなく、画像は利用者のブラウザの外に出ない（送るのは Pyodide 本体を読み込む通信だけ）
- **CLI と画面で結果をそろえる**: 入口は `convert.py` の `convert_sprite(rgba, SpriteSettings)` 1 つ（工程の組み立て `build_pipeline()` もここだけ）。
  画面は `convert_for_web()`・`motion_for_web()`・`gif_for_web()`・`frames_*_for_web()`・`readback_for_web()` を呼ぶ（中身は CLI と同じ関数）。既定値も同じ
- **1 枚で動く HTML**: ひな形 `apps/sprite/web/template.html` に `tools/build_sprite_web.py` で retrocore の .py と設定の選択肢を埋め込み `sprite-app.html` にする（直接編集しない。
  古くないかはテストで確かめる）。ダウンロードしてダブルクリックで開ける。公開する場所は未定
- Python は Web Worker の中で動かす（画面が固まらない）。設定を変えたときは変換をやり直さず動きだけを作り直し、入力が続くときは 0.25 秒待って最後の 1 回だけ作る
- 初心者向けに、毎回使うもの（画像・動き・重ね・② 変換する・再生・保存）を作業の順に前に出し、たまに使う設定は「必要なときに開く」「細かい設定」に折りたたむ（閉じていても効く。既定から変えた設定があると見出しに「（変更あり）」）。表・範囲・直しは開いたときだけ出す
- 保存は「まとめて保存（ZIP）」を前に出し（1 つのボタンで何個ものファイルを続けて保存すると、ブラウザが止めることがあるため 1 つの ZIP にする。日時を固定して同じ入力なら同じ ZIP）、ファイルごとのボタンは「1 つずつ保存」に残す。.piskel と読み戻しは「外のエディタで直す」
- 確認の窓は自前（ブラウザの OK／キャンセルは「キャンセル」を「やめる」と読み違えやすい）
