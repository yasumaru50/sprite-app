## 土台づくり（CG 変換アプリと共通ライブラリ）

### #1 CG 変換アプリの最初の版
- Windows 用のデスクトップアプリ（Python・PySide6・NumPy・Pillow）。古いパソコンの解像度への縮小、2〜256 色への減色、ディザ
- お手本の画像から色（パレット）を取り出して、別の画像に当てる「パレット・トランスファー」
- PyInstaller で 1 つの exe にし、GitHub Actions でビルドする

### #2 スタイル変換・スタイルの解析・自動調整
- 色相ごとの明暗の段（ランプ）、グラデーションの所だけのディザ、ベタ塗り、輪郭線で当時の CG らしさを出す「スタイル変換」（オプトイン）
- お手本の特徴（色数・ディザの割合・輪郭など）を JSON に取り出す解析と、それを設定に直す自動調整、年代と技法で名前を付けたプリセット 5 種
- 決めたこと: 新しい機能はすべてオプトインにし、既定の出力を変えない。変換の中身は NumPy と Pillow だけで書く

### #3 混色の統計・データの書き出し・ランプをまたいだ混色
- ディザで混ぜている 2 色の関係（同じランプの隣・ランプ間など）の統計
- 解析の結果を JSON・パレット・CSV に書き出す道具（画像そのものは書き出さない）
- 別のランプの近い色どうしも混ぜられる設定（既定は切）。既定の出力が前と同じことをハッシュで確かめた

### #4 CLAUDE.md を足す
- リポジトリの概要・構成・開発ルール（中身は NumPy と Pillow だけ、既存の動きを変えない、テスト画像はコードで合成、作品名を使わない など）

### #5 CI の直し
- exe の保存先の容量が足りずにビルドが失敗していた。保存期間を 7 日にし、PR のときは保存しないようにした（アプリは変えていない）

### #6 回帰テスト（ゴールデン）
- 今の変換の結果を「期待値」として保存し、同じ条件で作り直して画素・バイト単位で比べるテスト（52 ケース）
- 決めたこと: Windows と Linux の改行の違いだけはそろえて比べる。意図して出力を変えたときだけ期待値を作り直す

### #7 共通ライブラリ `retrocore/` を作る
- 変換の中身をアプリから切り離し、リポジトリ直下の `retrocore/` に移した（動きは変えていない）
- `retrocore/` が NumPy・Pillow・標準ライブラリ以外を読み込まないことを確かめるテストを足した（ブラウザの Pyodide で動かすため）

## Sprite App フェーズ 1：AI 画像 → スプライト

### #8 Sprite App のひな形
- `apps/sprite/` に CLI（`python -m apps.sprite`）、`retrocore/sprite/` に工程を順に実行する仕組み（`Step`・`SpritePipeline`）と縮小
- テスト用のキャラはコードで合成する（`tests/synth_sprite.py`）。手持ちの画像を試す `local_samples/` は Git に入れない

### #9 ドット絵向けの縮小
- ブロックの中で最も多い色（mode）・中央値（median）を選ぶ縮小と、暗い線を優先する「線優先」。新しい色は作らない

### #10 CLI の既定を mode＋線優先に
- 縮小の既定を mode＋線優先にした（共通ライブラリの既定は変えていない）。拡大したプレビューを書く `--preview-scale`

### #11 計画書を新しい方針に合わせる（文書だけ）
- 普通のイラストを縮小すると「8 ビットゲーム」風になり、目指す見た目と違った
- 決めたこと: 目指すのは今のインディーゲーム風のドット絵（平塗り・ディザなし）。主な入力は AI が描いた「ドット絵風の画像」（ドット 1 個が約 20px）。
  工程の順番は 背景除去 → グリッド検出または縮小 → 単純化 → クリーンアップ → 縁取り → パレット

### #12 背景除去
- 外周から背景色を推定し、外周からつながった背景だけを透明にする。中にある同じ色の白い服などは残る
- 決めたこと: 許容量の既定は 32（背景のにじみは消え、輪郭のそばの明るい色は残る値を ai01〜ai03 で探した）

### #13 グリッド検出
- ドット絵風の画像からドットの境目を見つけ、1 ドット＝1 画素に戻す。大きさは自己相関、線の位置は動的計画法で決める
- 決めたこと: ドットは既定で正方形とみなす（縦横を別々に推定すると縦長に見えた）。見つからないときは変換せずに理由を出す。
  CLI の入力の種類は `--input-type pixel`（既定）と `illust`

### #14 単純化（似た色をまとめる）
- OKLab で色の近さを測り（色みは 1.5 倍に重く）、近い色から順にまとめる。面積で重みを付けないので、目・頬のような小さな色も残る
- 決めたこと: ぼかしの名残の中間色は軽く数える。残す色は実在する色にする（色が濁らない）

### #15 クリーンアップ
- 溶け込む孤立ドット、中間色の小さな塊、輪郭の L 字の角などを、まわりの色に置き換える（強さ off・light・normal・strong）
- 決めたこと: 新しい色は作らない。2 ドット以上つながった色は部品とみなし、目などの暗い 1 ドットは残す

### #16 縁取り
- 既定の `auto` は、すでに暗い輪郭があれば切れ目だけを埋め、無ければ外側に 1 ドットの輪郭を付ける（`add`・`off` も選べる）
- 輪郭の色は既定で内側の色を暗くした色

### #17 クリーンアップと縁取りの直し
- ai04・ai05 で見つかった問題（目・口・ハイライト・影が消える、面を横切る切れ目を埋めてしまう）を直した
- 決めたこと: 考え方は「迷ったら何もしない」

### #18 ごく近い色を必ずまとめる
- 色数の上限に関係なく、見分けられないほど近い色は 1 色にまとめる（`--merge-distance`、既定 0.03）。既定の色数を 12 にした（後に #39 で 16 へ）

### #19 パレット統合の第一歩
- 使った色を保存する `--save-palette` と、指定したパレットの色だけで描く `--palette`（`.hex`・`.gpl`・`.png`）
- 決めたこと: パレットに無い色は足さず、別の部品の色が同じ色になったときなどは警告する

### #20 ブラウザ版の最初の版
- `retrocore/` をそのまま Pyodide で動かす 1 枚の HTML（`apps/sprite/web/sprite-app.html`）。画像はブラウザの外に送らない
- 決めたこと: CLI と画面の入口を `convert_sprite()` 1 つにして、結果をバイト単位でそろえる。HTML はひな形から道具で作り、直接編集しない

## Sprite App フェーズ 2：動き

### #21 動きの土台と「呼吸」
- 変換後のスプライトを材料に、体の上の部分を 1 ドット下げて戻す呼吸。縦に同じ色が続く所から 1 ドット抜く
- 決めたこと: 変換の工程には手を入れない。新しい色を作らない・大きさと足元をそろえる・輪郭を途切れさせない・迷ったら動かさない、を毎回確かめる

### #22 呼吸の分ける高さを指定する
- `--breathe-split`（下から何ドット目か）。決まりを守れないときは動かさず、近くで分けられる高さを知らせる
- 決めたこと: 黙って別の高さに移さない（成功したように見えてしまうため）

### #23 ブラウザ版で呼吸を再生・保存
- 「動き」の欄、繰り返し再生、背景の切り替え、行の番号、シート（PNG）と情報（JSON）の保存。Python は Web Worker の中で動かす
- 32 ビットの NumPy（Pyodide）を想定した確かめを CI の int32-check で動かす

### #24 横揺れ
- 足元は動かさず、体の上の部分が左右に揺れる。はみ出す分は左右に透明の列を足す

### #25 浮遊と、足元が動く動きの例外
- キャラ全体を上下に動かす浮遊
- 決めたこと: 足元が縦に決まった量だけ動くことだけを例外として許す（ほかの決まりは同じ）

### #26 動きを数の表で書く設計（文書だけ）
- 動きを「行 = フレーム、列 = 動かし方」の表（`.motion.json`）で書く設計
- 決めたこと: 高さは数か割合で保存を選べる。足元が動いてよいのは体全体のずれ（`root`）の列だけ。この先の PR の順番

### #27 動きの表の仕組みと CLI
- 表の読み込み・確かめ・書き出しと、表からフレームを作る仕組み。呼吸・横揺れ・浮遊を表を埋めるプリセットに作り直した
- 決めたこと: 作り直しても出力は 1 バイトも変えない（前の出力のハッシュと比べるテスト）

### #28 弾む
- キャラ全体が地面から上にだけ跳ねる（高さ 1〜3）。着地のフレームだけ表示時間を長く（300 ミリ秒、空中 150）

### #29 外部調査のまとめ（文書だけ）
- ドット絵の変換と動きについての外部の道具・考え方を `docs/research-2026-11.md` にまとめた（コードは写していない）

### #30 ブラウザ版の「表で編集」
- プリセットから表を開いて、行の追加・削除や数の変更をし、保存・読み込みができる。作れない行はマスを赤くする

### #31 うなずく
- 首を自動で探し、首から上を下げて戻す。首が見つからないときは付けずに、試せる高さを知らせる

### #32 伸ばす・伸び・小さな部品を守る
- 表の縦の変形の +（伸ばす）と、伸びのプリセット。上にはみ出す分は透明の行を足す
- 「小さな部品を守る」（目・頬などの長さを変えない。既定は切）

### #33 動かす範囲の帯と四角
- 表の範囲に帯（`band`）と四角（`rect`）を足した。囲んだ中だけが動き、境目で作れないときは作らずに近くの範囲を知らせる

### #34 ブラウザ版で範囲を描く
- 「表で編集」で、絵の上をドラッグして帯・四角を作る・直す・消す（`retrocore/` は変えていない）

### #35 作らなかった理由を JSON に残す
- シートの JSON を版 2 にし、作れなかった理由（`skipped`）を残す。作れなかったときは `_skipped.json` を書く
- 決めたこと: 新しい判定は足さず、今ある警告を写すだけ

### #36 GIF アニメの書き出し
- シートと同じ絵・同じ時間の GIF（拡大 1〜8 倍、透明か背景色）。シートの JSON は変えない

## コマが並んだ絵と手直し

### #37 横に並んだコマをそろえる
- 歩き・走りのように横に並んだコマを切り分け、同じグリッド・同じパレット・同じ大きさ・同じ足元のシートにする（`--frames`）
- 決めたこと: ドットの大きさは全部のコマで 1 つ、線の位置はコマごとに合わせる。ちらつきは見える化だけ（自動では直さない）

### #38 淡い色が青っぽくなる件・正面歩きの幅のぶれ
- 単純化で淡い色どうしがまとめられていたので「大きな面の色を守る」（`keep_large`、既定 0.01）を足した
- 形の似たコマはグリッドの線を共通にする（`--frame-grid`、既定 `auto`）

### #39 色数の既定を 16 に・ブラウザ版で「コマが並んだ絵」・Piskel 向けの名前
- 色数の既定を 16 にした。ブラウザ版でコマが並んだ絵を変換・再生・保存できる
- コマのシートの名前に 1 コマの大きさとコマの数を入れた（Piskel に読み込むとき迷わないように）。手直しの手順 `docs/sprite-edit.md`

### #40 手直ししたシートの読み戻しと .piskel
- Piskel などで直したシート（PNG か .piskel）と元の JSON から、JSON・GIF・反転などを作り直す（`--readback`）。.piskel の書き出しと読み込み
- 決めたこと: 直したドットはそのまま使い、新しい色などは作って警告する（直すのは利用者が選んだときだけ）

### #41 縁取り thin
- 2 ドットの太さになった外側の輪郭を 1 ドットにする `thin`（既定は `auto` のまま）
- 調べて分かったこと: 太い輪郭は縁取りで足したものではなく、元の絵のドット 1 個を 2 ドットに読んでいたため

### #42 ちらつきを自動で減らす
- 2 コマ目以降の上の方の小さな違いを 1 コマ目の色に戻す（`--steady on`、既定 off）

### #43 範囲を 1 コマ目と同じにする
- 人が選んだ範囲（頭など）を、位置を探して 1 コマ目のドットにする（`--same-as-first`）。合わないコマは写さずに警告する

### #44 ブラウザ版の「ドットを直す」
- 画面の中で数ドットを直すエディタ（ペン・消しゴム・スポイト・元に戻す）。直しの一覧を保存でき、CLI の `--edits` でも当てられる
- 決めたこと: 直しは元のコマごとに持ち、パレットに無い色は作らない。直しが無いときの出力は前と同じ

### #45 直しがあるときに画像を選び直す
- 直しが残ったまま画像を選び直したり入力の種類を変えたりしたら、確認の窓を出す（保存してから捨てる・保存せずに捨てる・新しい画像にも当てる・やめる）

- 別々のファイルの絵をつなげる（`retrocore/sprite/join.py`、CLI の `--frames --join`・`--join-match-height`、画面の「つなげるファイル」の一覧と ▲▼・外す・足す）:
