# Still App（1 枚絵）の使い方

AI が「PC-98 のゲーム CG 風」などに描いた **ドット絵風の 1 枚絵**（背景も絵の一部）を、本物のドット絵
（1 ドット＝1 画素・決まった色数・ディザは選んだときだけ）にそろえる。98 の条件に全部従わせるのではなく「98 風」を目指す。
「今風」モード（`--mode modern`）は、最近のインディーゲームの背景のような「今のドット絵」の手直しの出発点を作る（98 の雰囲気は狙わない）。
「写真の下書き」モード（`--mode photo`。試しの機能）は、自分で撮った写真（部屋・建物）を、Pixelorama などで塗り直す出発点になる「色を塗り分けた下絵」にする（完成したドット絵は目指さない）。
## モード＝初めの設定

98 風・今風・写真の下書きの「モード」は、別々の工程ではなく、**1 本の工程の項目の値の組み合わせ（初めの設定）**。
工程は いつも 向きを直す → マス目を決める → 比率に合わせて切り抜く → 色の塊をまとめる → 減色 → 似た色をまとめる → ディザを作る → 孤立したドット → 模様を整える → 輪郭 → 余白 の順で、
初めの設定はそれぞれの項目を入・切にしたり値を決めたりしているだけ。どの項目も、どの初めの設定からでも 1 つずつ変えられる
（CLI はオプション、ブラウザ版は「必要なときに開く」）。たとえば「今風でマス目を探したうえで色の塊を弱くまとめる」（`--mode modern --smooth weak`）や
「写真の下書きを 16 色＋4096 色に丸め」（`--mode photo --colors 16 --4bit`）もできる。

| 項目（工程の順） | PC-98 風（`pc98`） | 今風（`modern`） | 写真の下書き（`photo`） | CLI |
| --- | --- | --- | --- | --- |
| 写真の向き（EXIF）を直す | 切 | 切 | 入 | `--orient`・`--no-orient` |
| マス目の決め方 | マス目を探す | マス目を探す | 横 320 マスで分ける | `--grid`・`--width N` |
| 比率に合わせて切り抜く | 元のまま | 元のまま | 元のまま | `--aspect W:H`・`--anchor X,Y` |
| 大きさの上限 | 640×400 | 1920×1080 | 1920×1080 | `--max-size` |
| 色の塊をまとめる | しない | しない | 中 | `--smooth off・weak・medium・strong` |
| 色数 | 16 | 32 | 32 | `--colors` |
| 4096 色に丸める | 入 | 切 | 切 | `--4bit`・`--no-4bit` |
| いちばん暗い色を取っておく | 入 | 入 | 入 | `--keep-darkest`・`--no-keep-darkest` |
| 似た色をまとめる | 切 | 入 | 切 | `--merge-similar`・`--no-merge-similar` |
| ディザを作る | しない | しない | しない | `--dither off・2x2・4x4` |
| 孤立したドットをそろえる | 切 | 切 | 入 | `--tidy-dots`・`--no-tidy-dots` |
| ざらついた範囲を模様に整える | 切 | 切 | 切 | `--tidy-pattern` |
| 輪郭の線 | 切 | 切 | 切 | `--outline` |
| 余白（キャンバス） | なし | なし | なし | `--canvas` |

初めの設定から変えた項目があると、ブラウザ版では「初めの設定」の横と「必要なときに開く」の見出しに「（変更あり）」が出て、
JSON には `preset`（初めの設定の名前・変えた項目・項目の値すべて）が入る。初めの設定のままなら、出力は前の版とバイト単位で同じ。

ブラウザ版と CLI は同じ Python のコード（`retrocore/still/`。グリッド検出と色の選び方は Sprite App の `retrocore/sprite/` を使う）で動き、
同じ設定なら PNG と JSON はバイト単位で同じ。オプションと JSON の形は [docs/cli.md](../../docs/cli.md#1-枚絵still-app) の「1 枚絵（Still App）」。

## ブラウザ版

1. GitHub で `apps/still/web/still-app.html` を開き、右上の「Download raw file」を押す
2. ダウンロードした `still-app.html` をダブルクリックして、ブラウザ（Chrome・Edge など）で開く
3. 「準備ができました」と出たら（初回は 10〜30 秒）、画像（PNG・JPEG。HEIC は読めない）を選ぶ → 変換 → 「PNG を保存」「JSON を保存」

- 元の絵と結果を横に並べて見られる（拡大はニアレストネイバーで、倍率を選べる）。パレットの色見本も出る
- 「初めの設定」で「PC-98 風」「今風」「写真の下書き」を選ぶと、「必要なときに開く」の項目に、その組み合わせの値が入る
- 「必要なときに開く」の項目は工程の順（写真の向き・マス目の決め方・横のマス数・比率に合わせて切り抜く・切る位置・大きさの上限・色の塊をまとめる・色数・4096 色に丸める・いちばん暗い色・
  似た色をまとめる・ディザを作る・孤立したドット・模様を整える・輪郭の線・余白）。どの初めの設定でも全部変えられる。色数は 2〜256 を入れられ、16・24・32・48・64・96・128 が候補に出る。
  初めの設定から変えると、赤で「（変更あり）」
- 「初めの設定」と「必要なときに開く」の全部の項目の横に「？」がある。押すと、その項目のすぐ下に 3 行の説明が開き、もう一度押すと閉じる
  （「オンにすると」（選ぶ項目は「選ぶと」、数を入れる項目は「入れると」）・「気を付けること」・「向いている絵」と、CLI のオプション）。
  初めの設定の「？」は 3 つの初めの設定をまとめて出し、選んでいるものに青い線が付く。「説明をすべて表示」で全部を一度に開ける。
  説明の文は `retrocore/still/guide.py` の 1 か所にあり、CLI の `--help` も同じ文を使う
- 「必要なときに開く」の「ざらついた範囲を模様に整える」に印を付けると、ディザ風の所を 2 色の決まった模様に整える（CLI の `--tidy-pattern`）。
  変換した後は「整えた範囲を色で重ねる」で、整えた範囲を薄い色（縁は濃い色）で結果に重ねて見られる（表示だけで、保存する PNG は変わらない）
- 「ディザを作る」で「2×2（5 段）」か「4×4（17 段）」を選ぶと（CLI の `--dither`。どの初めの設定でも既定は「しない」）、空のようになめらかに色が変わる所で、
  近い 2 色の間を決まった網目でつなぐ（下の「ディザを作る」）。変換した後は「網目を入れたドットを色で重ねる」で、色を変えたドットを濃い緑、
  網目の範囲のほかのドットを薄い緑で結果に重ねて見られる（表示だけ）
- 「孤立したドットをそろえる」に印を付けると（CLI の `--tidy-dots`）、変換した後に「置き換えたドットを色で重ねる」で、置き換えたドットを
  濃い桃色（まわり 1 ドットは薄い桃色）で結果に重ねて見られる（表示だけ）
- 「輪郭の線を引く」に印を付けると（CLI の `--outline`。どのモードでも既定は切）、変換した後に「線を引いたドットを色で重ねる」で、
  線にしたドットを水色で結果に重ねて見られる（表示だけ）
- 「比率に合わせて切り抜く」で 16:9・16:10・4:3・3:2・1:1 か「数値で入れる」を選ぶと、拡大・縮小なしで その比率に切り抜く（下の「比率に合わせて切り抜く」）。
  「切る位置」は 3×3 のボタン（左上〜右下）か、横・縦の % の欄。16:9 のときは横のマス数の候補 320・480・640 のボタンが出る（押すと「横のマス数で分ける」にしてその数を入れる）。
  切り抜いたときは、「元の絵」に切り抜いた範囲だけを結果と同じ大きさで出す
- マス目が見つからないとき・大きさの上限を超えたときは、横のマス数の候補のボタンが出る（押すとその数で変換する）
- いちばん下に Pyodide の版とビルド番号が出る

## CLI

```bash
python -m apps.still 入力.png --mode pc98 --out out/still/部屋      # → 部屋.png（インデックスカラー）と 部屋.json
python -m apps.still 入力.png --width 160                           # マス目を探さずに、横 160 マスに縮める
python -m apps.still 入力.png --colors 8 --canvas 640x400          # 8 色、余白を足して 640×400 に
python -m apps.still 入力.png --width 600 --tidy-pattern            # ざらついた範囲を 2 色の模様に整える
python -m apps.still 入力.png --mode modern                         # 今風（32 色・丸めない・1920×1080 まで・似た色をまとめる）
python -m apps.still 入力.png --mode modern --tidy-dots             # 孤立したドットもそろえる
python -m apps.still 写真.jpg --mode photo                           # 写真の下書き（横 320・まとめの強さ 中）
python -m apps.still 写真.jpg --mode photo --smooth strong --outline # まとめを強く、輪郭の線も引く
python -m apps.still 写真.jpg --mode photo --width 480 --no-tidy-dots
python -m apps.still 入力.png --mode modern --width 600 --smooth weak # 今風＋色の塊を弱くまとめる
python -m apps.still 写真.png --mode photo --width 640 --colors 16 --4bit  # 写真の下書き＋16 色＋4096 色に丸め
python -m apps.still 入力.png --mode photo --grid                    # 写真の下書きの工程で、マス目を探す
python -m apps.still 写真.jpg --mode photo --width 640 --colors 16 --4bit --dither 2x2   # 空などに 2×2 の網目
python -m apps.still 写真.jpg --mode photo --width 1280 --dither 4x4  # 4×4（17 段）の網目
python -m apps.still 写真.jpg --mode photo --aspect 16:9              # 16:9 に切り抜く（横 320 → 320×180。ゲームの背景）
python -m apps.still 写真.jpg --mode photo --aspect 16:9 --anchor 50,20   # 切る位置を上寄りに（横 50%・縦 20%）
python -m apps.still 写真.jpg --mode photo --width 640 --aspect 16:10 --colors 16 --4bit --dither 2x2   # 640×400（写真の 98 風）
python -m apps.still 入力.png --mode modern --aspect 16:9             # マス目を探したあと、マス単位で 16:9 に切る
python -m apps.still 入力.png --mode modern --width 1200 --aspect 1200:630   # サイトの見出し画像の比率（数値で）
```

`--mode` を付けないときは `--mode pc98`。初めの設定の値と、変えるオプションは上の「モード＝初めの設定」の表。
`--grid` と `--width` は一緒に使えない（マス目を探すか、横のマス数で分けるかのどちらか）。

## 写真の下書き（試しの機能）

自分で撮った写真から、塗り直しの下絵を作る。写真の下書きの初めの設定のときの工程は 写真の向きを直す → 仕上がりの 4 倍の大きさに縮める（ブラウザ版を軽くするため）→
**色の塊をまとめる** → 仕上がりの大きさに縮める（マスはいちばん多い色）→ 減色（今風と同じ。ただし似た色はまとめない）→ 孤立したドット → 輪郭の線（`--outline` のとき）→ 余白。

- 色の塊をまとめるのは桑原（Kuwahara）フィルタ: 各画素で、その画素を角に含む 4 つの正方形のうち、明るさのばらつきがいちばん小さいものの平均の色にする。
  境目をまたぐ正方形は選ばれないので、境目は残ったまま、似た色の近所がならされる。強さは 弱（半径 2・1 回）・中（半径 4・2 回）・強（半径 5・3 回）
- 輪郭の線（`--outline`）: 明るさ（OKLab の L）の差が 0.25 以上の色の境目に、暗い方の側へ 1 ドットの線を引く。線はパレットのいちばん暗い色（新しい色は作らない）
- JPEG の入力では、CLI とブラウザ版で結果が少し違うことがある（JPEG を画素に戻すライブラリが違うため。CLI は libjpeg-turbo、ブラウザ版は IJG libjpeg 9）。
  同じ結果がほしいときは、先に PNG にしてから通す（PNG ならバイト単位で同じ）
- 色の塊をまとめるのは、ほかの初めの設定でも使える（`--smooth`）。マス目を探したときは、見つけたマスを 4×4 の画素に縮めてからまとめる
  （マスが 4px より小さいときは縮めずに元の画素で）。1 ドットの細い線は、ところどころ途切れることがある
- 比較の画像は `preview/ai-check` ブランチの `ai-output/still-04/`（強さの違い）と `ai-output/still-05/`（今風＋色の塊・写真の下書き＋16 色＋4096 色）

## 今風モードで色のにじみを減らす

色数を増やすと、AI のにじみの色（境目の中間の色・ぽつんとした点）がパレットに残りやすい。今風モードでは 2 つで扱う:

- **似た色をまとめる**（今風の既定。98・写真の下書きでも `--merge-similar` で使える。写真の下書きでは、近い色が空などの段として要るので既定は切。
  まとめると photo03 で 16 色が 11 色に減り、空の段が粗くなった）: 減色のあと、見た目でほぼ区別できない色どうし（OKLab の距離 0.04 未満）を、ドット数の多い方の色にする。
  いちばん暗い色は残す側。色数は上限なので少なくなることがある（まとめた組は警告と JSON の `similar` に出る）。新しい色は作らない
- **孤立したドットをそろえる**（`--tidy-dots`、どのモードでも既定は切）: まわりの 8 ドットに同じ色が 1 つも無く、7 つ以上が同じ色 A のドットを A にする。
  いちばん暗い色のドットと絵の端のドットは変えない。1 回だけ通す。比較の画像は `preview/ai-check` ブランチの `ai-output/still-03/`

## ディザを作る（`--dither 2x2`・`4x4`）

写真の空のようになめらかに色が変わる所で、減色で分かれた隣り合う 2 色の間を、決まった網目（Bayer 型）でつなぐ。90 年代の PC の取り込み画像のようなグラデーションになる。
どの初めの設定でも既定は「しない」（off）。工程の場所は、減色・似た色をまとめるの後、孤立したドットをそろえるの前（`retrocore/still/dither.py`）。

- **パレットは変えない**: 選ばれる色はディザなしのときと同じ。新しい色は作らず、どのドットにどちらの色を置くかだけを変える
- **なめらかな所の見分け方**: 減色する前のドットの色で、となりどうしの色の差（OKLab）が 0.03 以上の所が、まわり 5×5 に 1 つも無いドット（つながりが 64 ドット以上）。
  輪郭・はっきりした境目・木の葉のような細かい描き込みは差が大きいので入らない
- **混ぜる 2 色**: まわり 5×5 の色の平均にいちばん近い色と、その色から OKLab で 0.15 未満の、平均を間にはさむ色。離れた色どうし・いちばん暗い色は混ぜない。
  ディザなしで 2 色のどちらかだったドットだけを変える（3 色目のドットはそのまま）
- **網目**: 2×2 は 5 段（0・25・50・75・100%。「模様を整える」と同じ表）、4×4 は 17 段。表の位置は絵全体で共通の座標なので、範囲の境目でも網目がずれない
- 網目の範囲のドットは「孤立したドットをそろえる」で消されず、「模様を整える」でも作り直さない
- JSON の `dither` に、網目で色を変えたドット数（`changed`）・網目の範囲のドット数（`area`）・2 色の組の数（`pairs`）・中で決めたしきい値が入る
- 比較の画像は `preview/ai-check` ブランチの `ai-output/still-06/`

## 比率に合わせて切り抜く（`--aspect W:H`・`--anchor X,Y`）

スマホの写真（4:3・縦長）や AI の絵（3:2）を、16:9（ゲームの背景）・16:10（PC-98 の 640×400）・サイトの見出し画像などの比率に、**拡大・縮小なしで、切り抜くだけで**合わせる。
余白を足して合わせたいときは `--canvas`（切り抜いたあとに足すこともできる）。どの初めの設定でも既定は「元のまま」（`retrocore/still/aspect.py`）。

- **比率**: 正の整数どうし（例 16:9・21:9・1200:630）。0・小数・文字は「比率（--aspect）は 幅:高さ を正の整数どうしで…」のエラーで止める
- **切る位置**: 横・縦それぞれ 0〜100 の%。50,50 は中央、50,0 は上寄せ、0,50 は左寄せ、50,20 は少し上寄り
- **横のマス数で分けるとき**（写真の下書きの既定）: 入力の段階で切り抜いてから工程に通す。縦のマス数を先に `横のマス数 × 比` の四捨五入で決め、
  入力をちょうどその比に切るので、横 320・16:9 はちょうど 320×180、横 640・16:10 は 640×400。割り切れないとき（横 300・16:9 → 168.75）は四捨五入（169）
- **マス目を探すとき**: マス目を見つけたあと、マス単位で切る（格子はずれず、残ったマスの色は切り抜く前と同じ）。長すぎる方のマスの数を四捨五入で決める
  （165×95 マスを 16:9 → 165×93。ちょうど 16:9 にならないことがある）。大きさの上限は切った後の大きさで確かめる
- JSON の `aspect` に、比率・切る位置・切った時点（`input`・`cells`）・残した範囲（入力の画素）・切り落とした画素とマスの数が入る
- 比較の画像は `preview/ai-check` ブランチの `ai-output/still-07/`

## 知っておくこと

- **出力は正方形のドット**。PC-98 の画面のドットは少し縦長（約 1：1.2）だが、それは再現しない
- 透明な所は黒で埋める（背景も絵の一部として扱う）
- 減色ではディザは使わない（`--dither` を選んだときだけ、上の「ディザを作る」で網目を入れる）。また `--tidy-pattern`（既定は切）では、AI がディザ風に描いて減色でばらばらの点になった所だけを、
  パレットの 2 色の 2×2 の決まった模様（濃さ 5 段。50% は市松）に置き換える。輪郭・平塗りの面・小さい所・3 色目（描き込み）が多い所は変えない。
  比較の画像は `python tools/compare_still_pattern.py 入力.png --width 600 --out out/still/比較 --crop 左,上,右,下`
- 大きな絵のドットの手直しは、Pixelorama などのドット絵のソフトで行う想定
- マス目が見つからないとき・大きさが上限を超えるときは、出力せずに止めて `--width` の候補を出す
