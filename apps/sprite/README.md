# Sprite App

AI 画像（主にドット絵風の AI 画像。後にラフな手描き）から、今のインディーゲーム風のドット絵スプライト（平塗り・ディザなし）を作るアプリ。設計は [docs/sprite-app-plan.md](../../docs/sprite-app-plan.md)。

フェーズ 1 は CLI で処理を検証する。現在できるのは **背景除去**、入力の種類（`--input-type`）に応じた次のどちらか、
そのあとの **単純化**（似た色をまとめる。見分けのつかない色は必ず 1 色にし、既定で 16 色以下）、**クリーンアップ**（余計なドットをまわりの色に置き換える。既定 `normal`）、
**縁取り**（キャラクターの外側の輪郭を整える。既定 `auto`）、**パレット**（使った色をパレットファイルに保存する
`--save-palette`、指定したパレットの色だけで出力する `--palette`。どちらも指定したときだけ）。

- `pixel`（既定）: **ドット絵風の画像**（AI が描いた、ドット 1 個が約 20px の画像）。ドットの境目（グリッド）を見つけて、
  1 ドット＝1 画素の本物のドット絵に戻す。出力の大きさは自動で決まる（キャラクターの大きさに切り詰める）
- `illust`: **普通のイラスト**。指定サイズに縮小する。既定の縮小はドット絵向けの `mode`（ブロック内の最頻色）＋線優先。
  `nearest` などの一般的な縮小も選べる

入力の種類は使う人が選ぶ（自動判定はしない）。背景除去は既定で有効（元の大きさのまま、グリッド検出・縮小の前に行う）。

## ブラウザ版（試作）

`apps/sprite/web/sprite-app.html` は、CLI と同じ Python のコード（`retrocore`）をブラウザの中（Pyodide）で動かす 1 枚の HTML。
サーバーもインストールも要らない。画像はブラウザの外に送られない（インターネットには Pyodide 本体を読み込むためだけにつなぐ）。

1. GitHub でこのファイル（`apps/sprite/web/sprite-app.html`）を開き、右上の「Download raw file」（下向き矢印）を押す
2. ダウンロードした `sprite-app.html` をダブルクリックして、ブラウザ（Chrome・Edge など）で開く
3. 「準備ができました」と出たら（初回は 10〜30 秒）、画像を選んで「② 変換する」→「③ 結果を PNG で保存」

変えられる設定は色数・クリーンアップ・縁取り（既定値は CLI と同じ）。入力はドット絵風の画像だけ。
入力の種類は「1 枚の絵」（既定）と「コマが並んだ絵」（CLI の `--frames`。下の「画面でコマが並んだ絵を変換する」）。
結果は CLI の `python -m apps.sprite 入力.png --colors N --cleanup L --outline M` と同じになるように、
どちらも `retrocore/sprite/convert.py` の `convert_sprite()` を使う。
HTML はひな形 `apps/sprite/web/template.html` から `python tools/build_sprite_web.py` で作る（直接編集しない）。

### 画面でコマが並んだ絵を変換する（歩き・走りなど）

AI に描かせた歩き・走りのように、同じキャラが横に何コマも並んだ絵を、1 つのキャラとしてそろえたシートにする（CLI の `--frames` と同じ）。

1. 画像を選び、「**コマが並んだ絵**」を選ぶ
2. 「コマの数」に絵のコマの数を入れる（空なら自動。数を入れておくと、数え間違えたときに作らずに知らせる）。
   歩きは「縦のそろえ方」を「足元」（既定）、足が地面から離れる走り・跳びは「頭の高さ」にする。
   「ちらつきを減らす」を「あり」にすると、上の方の小さな違いを 1 コマ目の色に戻す（CLI の `--steady on`。既定は「なし」）。
   変換すると、各コマで戻したドットの数が画面の上の知らせと「コマの再生と保存」の説明に出る
3. 「② 変換する」→ 左の「元の画像」に見つけたコマの赤い枠と番号、右の「変換結果」にそろえたコマが並ぶ
   （ai07〜ai09（1774×887）で 4〜7 秒。数が合わないときは枠が橙になり、「作らなかった理由を保存（JSON）」が出る）
4. 下の「コマの再生と保存」で再生する（⏸／▶・1 コマ送り・背景は動きの欄と同じ）。「順番」（`1,2,3,2` など。「行って戻る」ボタンで入る）、
   「1 コマの時間」、「体の上下」（なし／あり 0,-1,0,-1 など）、「名前」（walk・run）は、変えるとすぐ作り直す（変換はやり直さない）
5. **1 コマ目と同じにする範囲**（頭など。CLI の `--same-as-first`）: 「コマの再生と保存」の下の欄に 1 コマ目が拡大して出るので、
   **マウスで左上から右下へドラッグ**して頭を囲む（何個でも足せる。「描く形」を「帯」にすると横いっぱい）。離すとすぐ 2 コマ目以降に写し、
   コマごとの「見つけたずれ」「合い方」「写した／写さなかった（理由）」の表と、範囲の図が出る。写した結果がそのまま再生・保存に入る。
   **描いた範囲は直せる**: 辺・角をドラッグすると大きさ、内側をドラッグすると位置が変わる（つかめる所ではマウスの形が変わる）。
   範囲が複数あるときは、クリックか一覧で選んだ範囲を直す。キーボード（絵をクリックしてから）: 矢印 = 1 ドット動かす、Shift＋矢印 = 右下の角を
   動かして大きさを変える、Delete = 選んだ範囲を消す、Esc = 選ぶのをやめる、Ctrl＋Z = 元に戻す。計算はマウスを離したとき・キーを止めたときだけ。
   範囲は一覧の「消す」・「選んだ範囲を消す」・「範囲を全部消す」で消せ、「元に戻す」で直す前に戻せる。
   「数で足す」に `x,y,幅,高さ` を入れても足せる
6. **ドットを直す**（ちらつき・ゴミ・輪郭の数ドットの直し。CLI の `--edits`）: その下の欄にコマが 12 倍で出る。
   色見本をクリックして色を選び、**左ドラッグで塗る**（速く動かしても前の点と線でつながる）。**右クリック・右ドラッグで透明にする**（消しゴム）、
   **Alt＋クリックで色を拾う**（スポイト。拾ったらペンに戻る）。使える色はシートのパレットだけ（新しい色は作れない）。
   キー（カーソルが絵の上にあるか、この欄を選んでいるとき。ほかの入力欄に文字を打つときは効かない）: B ペン／E 消しゴム／I スポイト／
   「,」「.」前後のコマ／O 前のコマを薄く重ねる・やめる／Ctrl＋Z 元に戻す／Ctrl＋Y か Ctrl＋Shift＋Z やり直し（1 回のドラッグを 1 つと数えて 50 回まで）。
   拡大は 4・8・12・16 倍、格子線は切り替えられる。カーソルの下の座標とパレットの番号が下に出る。横の小さな再生の見本は直すとすぐ変わる。
   直しは**元のコマごと**なので、順番 1,2,3,2 の 2 番目と 4 番目は 1 回直せば両方変わる。ドラッグを離すと、シート・JSON・GIF・反転・.piskel を作り直す。
   「1 コマ目と同じにする範囲」や変換の設定を変えても、直しはその上に重ね直す（直したときと下の色が変わったドットは橙の枠と警告で知らせる。
   「確かめた」で消える）。変換し直してコマの大きさ・数・パレットが変わり当てられないときは、確認の窓が出る: 「直しを保存してから捨てる」（おすすめ。edits.json を保存）、「保存せずに捨てる」、「やめる」（変換し直しを取り消して、前の結果・範囲・直し・入力欄の値に戻す。Esc でも同じ）。
   直しがあるときに画像を選び直す（同じファイルでも）と、新しい画像を変換した後に確認の窓が出る: 「直しを保存してから捨てる」（おすすめ）、「保存せずに捨てる」、
   「新しい画像にも当てる」（コマの大きさが同じときだけ。同じ絵を描き直したときなど。下の色が変わるドットの数が窓に出て、当てるとそのドットに橙の枠が付く）、
   「やめる（前の画像に戻す）」。直しがあるときに入力の種類を「1 枚の絵」に変えると、すぐに窓が出る（「やめる」で種類を戻す）。直しが無いときは窓は出ない。
   「直しの一覧を保存（JSON）」で `<出力名>_<名前>_edits.json` を保存でき、「直しの一覧を読み込む」で戻せる（CLI の `--edits` でも同じ直しを当てられる）
7. 保存: ③ そろえたコマを並べた絵、④ シート（PNG）、⑤ 情報（JSON）、⑥ GIF（拡大・背景は下の欄）、⑦⑧⑨ 左右反転のシート・JSON・GIF、
   ちらつきの見える化（PNG・JSON）、**Piskel で直す用（.piskel）**と左右反転の .piskel。④ か .piskel の保存を押すと
   「Piskel で直すときは：Import → Load .piskel file → Browse .piskel files」の案内が出る

保存したファイルは、同じ設定の CLI（画面の下に引数が出る。例 `--frames --frame-count 4 --frame-name walk --mirror --flicker --piskel`、
GIF は `--gif --gif-scale 8`）と**バイト単位で同じ**（`tests/test_sprite_frames.py`・`tests/test_sprite_edit.py`）。手直しの手順は [docs/sprite-edit.md](../../docs/sprite-edit.md)。

### 画面で直したシートを読み戻す（Piskel で手直ししたあと）

いちばん下の「**直したシートを読み戻す**」の欄で、ファイルを選ぶだけ（CLI の `--readback` と同じ。下の「手直ししたシートの読み戻し」）。

1. 「A. 直したファイル（.piskel か PNG）」に Piskel で保存した .piskel（Save → Save offline as File）か、書き出した PNG（Export → PNG）を選ぶ
2. 「B. 元のシートの情報（JSON）」にシートを保存したときの JSON を選ぶ（C. 直す前のシート（PNG）は、なくてもよい）
3. すぐに確かめた結果・作り直した動きの再生・確認の画像が出る。保存のボタン: 横 1 列に並べ直したシート（PNG）・シートの情報（JSON）・GIF・
   続けて直す用（.piskel）・左右反転のシート・情報・GIF・.piskel・確認の画像・記録、C を選んだときは直したドットの印（PNG）
4. 「同じコマを 2 回使う順番」（そのまま／先に出てくるコマに合わせる）・「おかしな色を直す」・「GIF の拡大」を変えると、すぐ作り直す

保存したファイルは、画面の下に出る CLI（例 `python -m apps.sprite 直した.piskel --readback 元.json --gif --mirror --piskel`）と**バイト単位で同じ**。

### 画面で動きを付ける（呼吸・横揺れ・浮遊）

変換したあと、画面のいちばん下の「動き」の欄で使う。「なし」（既定）のときは今までどおり（1 枚の PNG だけ）。

1. 「呼吸」「横揺れ」「浮遊」のどれかを選ぶ → 変換の結果から動きを作り、下の枠で繰り返し再生する（変換はやり直さない）
2. 必要なら設定を変える（変えるとすぐに動きだけ作り直す。既定値は CLI と同じ。動きごとの設定は別々に覚えておく）
   - **分ける高さ**（呼吸）・**揺れ始める高さ**（横揺れ）: 「自動」か「数字で指定」。数字は**下から何ドット目か**（1 = いちばん下の行）。
     「行の番号を表示」に印を付けると、プレビューの左に目盛りが出る（灰色の行は足元などで指定できない。選んだ高さに ▶ の印）
   - **フレーム数**（呼吸 2〜32・既定 2、横揺れ・浮遊 3〜32・既定 4）・**表示時間**（ミリ秒。`500` で全フレーム共通、`600,400` でフレームごと。
     既定は呼吸 500、横揺れ 300、浮遊 400）・**下がる量**（呼吸、1〜2 ドット）・**揺れ幅**（横揺れ・浮遊、1〜2 ドット）
   - 浮遊はキャラ全体を動かすので、分ける高さの欄は無い。行の番号は元の絵のいちばん下の行が 1（上下に足した余白の行は灰色）
   - 弾むは「弾む高さ」（1〜3 ドット）を選ぶ。フレーム数は高さで決まる（2・4・6）ので変えられない。表示時間の既定は着地だけ長め（`300,150,150,150`）
   - うなずくは「首の高さ（分ける高さ）」（自動は首を探す）と「下がる量」（深さ 1〜2）を選ぶ。フレーム数は深さで決まる（2・4）。
     表示時間の既定は上を向いているコマだけ長め（`600,200`）。首が見つからないと「試せる高さ: 5、9、13」と出るので「9 で試す」などを押す
   - 伸びは「分ける高さ」（自動は呼吸と同じ）と「伸びる量」（1〜2）を選ぶ。フレーム数は量で決まる（2・4）。上に伸びる分の透明の行が上に足される
   - 呼吸・うなずく・伸びには「**小さな部品を守る**」のチェックがある（既定は外れている）。印を付けると、目・頬など（同じ色の塊で縦 3 ドット以下・
     面積 24 ドット以下）の長さを変えずに縮める・伸ばす（その分、分けられる高さが減って作れないことがある）
3. 作れなかったときは黄色い枠に理由が出る（CLI の警告と同じ文言）。「近くで分けられる高さ: 11」と出たら「11 で試す」を押す。
   枠の下に小さく、JSON に書く記録の名前（`skipped` の `code`。例: `no_neck_found`）が出る。シートは保存できないが、
   「⑤ 作らなかった理由を保存（JSON）」で理由の JSON（CLI の `<名前>_<動き>_skipped.json` と同じ中身）を保存できる
4. 「再生 / 一時停止」「1 コマ戻す / 送る」で 1 枚ずつ見られる。背景は市松模様（透明の所が分かる）・白・黒などに切り替えられる
5. 「④ スプライトシートを保存（PNG）」と「⑤ シートの情報を保存（JSON）」で 2 つのファイルを保存し、同じフォルダに置く

保存したファイルは CLI の `python -m apps.sprite 入力.png -o <名前>_sprite.png --motion breathe ...`（横揺れは `--motion sway ...`、浮遊は `--motion float ...`、弾むは `--motion bounce ...`、うなずくは `--motion nod ...`、伸びは `--motion stretch ...`。同じ設定）が書く
`<名前>_sprite_breathe_sheet.png` / `.json`（横揺れは `_sway_sheet`、浮遊は `_float_sheet`、弾むは `_bounce_sheet`、うなずくは `_nod_sheet`、伸びは `_stretch_sheet`）と同じ中身（どちらも `retrocore/sprite/motion/` の同じ関数で作る）。
JSON の改行だけは、Windows の CLI が CRLF、画面が LF。

### 画面で表を編集する（表で編集・表を読み込む）

慣れてきたら、動きを「数の表」で細かく直せる（中身は CLI の `--motion-spec` と同じ。下の「動きの表」）。プリセットだけで使うなら、このボタンは押さなくてよい。

1. 「呼吸」などを選んで設定を決め、**「表で編集」**を押す → その設定のままの表が開き、丸いボタンに「表（自分で編集）」が出る
   （ファイルから始めるときは**「表を読み込む（.motion.json）」**）
2. 表の 1 行が 1 フレーム（いちばん左が「行（1 から）」、1 行目が「1 枚目」）。列は**表示時間**（ミリ秒）・**upper_x**（分け目から上の横。+ が右）・
   **upper_y**（分け目から上を縮める・伸ばす。− で下がる、+ で上がる）・**root_y**（体全体の上下。− が上。足元も動くのはこの列だけ）。空のマスは 0
   - 右の「↑ ↓ 複製 削除」で行を並べ替える・増やす・消す。「＋ 行を足す」で最後に 1 行足す（2〜32 行）
   - 表の上の**「動かす範囲」**の一覧に、範囲（分け目・帯・四角）が並ぶ。分け目は**高さ**を「自動」か「下から何ドット目」で決める。
     「部品を守る」に印を付けると、表に `"keep_small_parts": true` が入る（目・頬などの長さを変えない）。**動きの名前**はシートのファイル名（`<名前>_sprite_<動きの名前>_sheet.png`）になる
   - 範囲（帯・四角）を画面で作る手順は、次の「画面で動かす範囲を作る」
   - 数を変えると、少し待ってからプレビューを作り直す（打ち続けているあいだは待つ）
   - 同じ行で upper_x と upper_y を一緒に使うのは、まだ作れない（行を分ける）
3. 作れない行があると、**そのマスが赤くなり**、黄色い枠に理由（「2・6 行目（upper_y = −1、範囲 upper）: …」。行は 1 から）と
   「11 で試す（upper_y）」のボタンが出る。プレビューには分けられなかった高さに赤い帯が出て、シートは保存できない
4. **「表を保存…」**→ 高さの保存のしかた「数（このキャラ用）」か「割合（別のキャラにも使う）」を選んで「この形で保存」→ `<動きの名前>.motion.json`。
   CLI の `--write-motion-spec 表.motion.json --spec-height number|percent` と同じ中身で、`--motion-spec` でそのまま使える
5. 書き間違いのあるファイルを読み込むと、全部の問題を赤い枠にまとめて出し、表は変えない

### 画面で動かす範囲を作る（帯・四角）

分け目 1 本だと「分け目から上が全部動く」ので、剣のように分け目をまたぐ物も一緒に動く。**帯**（横いっぱいの、下の端〜上の端の行）や
**四角**（左・右・下・上で囲んだ所）にすると、**囲んだ中だけが動き、外は 1 ドットも動かない**（表の書き方は下の「動きの表」の「範囲」）。

1. 画像を変換し、「うなずく」など近い動きを選んで**「表で編集」**を押す（表のファイルから始めるなら「表を読み込む」）
2. 表の上の大きな絵（行・列の番号の目盛り付き。縦は下から、横は左から数える）の上で**ドラッグして四角を描く**
   （帯・四角を何も選んでいないとき。「＋ 四角」「＋ 帯」のボタンでも足せる。足元の斜線の行は範囲に入れられない）
   - 選んでいる範囲は太い枠と白い印で出る。**白い印（端）をつかむと端だけ**、**枠の中をつかむと全体**を動かせる。帯は上下だけ
   - 一覧の「下・上・左・右」の欄で 1 ドットずつ直せる（絵の上の枠と同じ数を出す）。名前の欄で名前を変え、「種類」で分け目・帯・四角を変え、「削除」で消す
   - 枠を押すとその範囲を選び、何も無い所を押すと選ぶのをやめる（次のドラッグで新しい四角）
3. **どの列をどの範囲で動かすか**を決める: 一覧の下の「upper_y をこの範囲（head）で動かす」を押すか、表の列の見出しの「範囲」で選ぶ。
   帯・四角だけの表では、使っていない分け目（範囲 upper）は一覧から隠れ、保存する表にも書かない（見出しで選び直すと戻る）
4. 範囲を変えると、少し待ってからプレビューを作り直す。作れないときは、黄色い枠に理由と**「案 1：範囲 head を … にして試す」**のボタンが出て、
   絵の上には**案の範囲が点線**（今の枠と違う所は薄く塗る）と「案 1」の札で出る。札かボタンを押すと、その範囲に切り替えて作り直す。
   作れない所のドットは赤い枠で出る
5. 「表を保存…」で「数」か「割合」を選んで保存（帯・四角の端も同じ。割合の左・右は、透明を除いたキャラの幅に対する割合）。
   読み込んだ割合の端で、直していないものは読み込んだまま書く。中身は同じ表を手で書いて CLI の `--write-motion-spec` に通したものと同じ

例（ai04 の剣を動かさずにうなずく）: 「うなずく」→「表で編集」→ 絵の上で左上（左 1・上 44）から右下（右 34・下 22）までドラッグ →
「upper_y をこの範囲（head）で動かす」。保存した表は `apps/sprite/examples/head_rect_nod.motion.json` を数で書いたものと同じ形になる。

| 画面 | CLI |
| --- | --- |
| 表（自分で編集） | `--motion-spec 表.motion.json` |
| 表を保存 → 数 / 割合 | `--write-motion-spec 表.motion.json --spec-height number` / `percent` |

## 使い方

リポジトリのルートで実行する（依存は `requirements.txt` と同じ。NumPy と Pillow のみ使う）。

```bash
# ドット絵風の画像（既定）
python -m apps.sprite 入力.png --preview-scale 10 -o out/sprite/出力.png

# 普通のイラスト
python -m apps.sprite 入力.png --input-type illust --scale 1/4 -o out/sprite/出力.png
```

| オプション | 内容 |
| --- | --- |
| `入力` | 画像ファイルまたはフォルダ（複数可）。フォルダは中の画像（png / jpg / webp / bmp / gif / tif）をすべて処理 |
| `--input-type` | 入力の種類。`pixel`（既定）= ドット絵風（グリッド検出）、`illust` = 普通のイラスト（縮小） |
| `--width W` / `--height H` | （`illust` のみ）出力サイズ。片方だけなら縦横比を保つ。両方なら縦横比を無視してそのサイズ |
| `--scale S` | （`illust` のみ）縮小倍率（`0.25` または `1/4`）。幅・高さとは同時に使えない |
| `--dot-size W[xH]` | （`pixel` のみ）ドットの大きさ（画素。`20` または `20x21`、小数可）。省略時は推定。指定すると「見つからない」の判定をしない |
| `--dot-shape` | （`pixel` のみ）ドットの形。`square`（既定）= 正方形とみなし、縦横の情報を合わせて 1 つの大きさを推定する。`separate` = 縦横を別々に推定する（横長・縦長のドットの画像向け） |
| `--grid-origin X,Y` | （`pixel` のみ）グリッドの始まる位置。指定すると線を色の境目に合わせず、等間隔の格子にする |
| `--grid-snap` / `--no-grid-snap` | （`pixel` のみ）グリッド線を近くの色の境目に合わせる（既定で有効）。無効にすると等間隔の格子 |
| `--grid-tolerance R` | （`pixel` のみ）線の間隔をドットの大きさの ±R 倍まで許す（既定 0.2） |
| `--background` / `--no-background` | 背景除去（既定で有効）。外周からつながった背景色の部分を透明にする。入力がすでに透過付きならそのまま通す |
| `--bg-color COLOR` | 背景色（`#RRGGBB` または `R,G,B`）。省略時は画像の外周から推定 |
| `--bg-tolerance T` | 背景色とみなす差（R・G・B の差の最大値、0〜255、既定 32） |
| `--bg-remove-enclosed` | キャラクターに囲まれた背景（髪の束の間、腕と体のすき間など）も消す。背景と同じ色の白い服なども消えるので注意 |
| `--resize-method` | （`illust` のみ。以下の縮小のオプションも同じ）`mode`（既定）/ `median` / `nearest` / `box` / `bilinear` / `lanczos`（下記） |
| `--mode-bin N` | `mode` で色をまとめる区間の幅（1〜256、既定 32）。大きいほど粗くまとめる。1 なら完全に同じ色だけを数える |
| `--line-priority` / `--no-line-priority` | 線優先（`mode` / `median` のみ）。暗い輪郭線の画素が一定割合以上のブロックは線の色を採用する。`mode` / `median` では既定で有効、`--no-line-priority` で無効。`nearest` などでは無効（明示すればエラー） |
| `--line-ratio R` | 線優先にする暗い画素の割合（0〜1、既定 0.25） |
| `--line-luma L` | 暗い画素とみなす輝度の上限（0〜255、既定 64） |
| `--colors N` | 単純化で残す色の数の上限（1〜256、既定 16）。透明は数えない |
| `--merge-distance D` | この距離（OKLab。色みは 1.5 倍で測る）より近い色は、色数の上限に関係なく必ず 1 色にまとめる（0〜1、既定 0.03）。`0` でまとめない（色数の上限だけで決める。以前の既定の動き）。大きくすると（0.06 など）色数ではなく近さで決められる |
| `--keep-large R` | 面積が全体のこの割合以上の色（肌・服・髪などの大きな面）どうしは、距離 0.06 以上の差があれば、ほかにまとめる組が無くなるまでまとめない（0〜1、既定 0.01 = 1%）。淡い肌や服が髪の色に吸われて全体が同じ色っぽくなるのを防ぐ。`0` で以前の動き |
| `--simplify` / `--no-simplify` | 単純化（既定で有効）。`--no-simplify` で無効（グリッド検出・縮小の結果をそのまま出す） |
| `--cleanup LEVEL` | クリーンアップの強さ。`off` / `light` / `normal`（既定）/ `strong`（下記） |
| `--no-cleanup` | クリーンアップしない（`--cleanup off` と同じ。単純化の結果をそのまま出す） |
| `--outline MODE` | 縁取りの動き方。`auto`（既定）/ `add` / `off`（下記） |
| `--no-outline` | 縁取りしない（`--outline off` と同じ。クリーンアップの結果をそのまま出す） |
| `--outline-color C` | 外側に付ける輪郭の色。`darken`（既定。すぐ内側の色を暗くした色）/ `single`（絵の中でいちばん暗い色の 1 色）/ 色の指定（`#3a2030` または `58,32,48`。その 1 色） |
| `--outline-shape S` | 外側に付ける線の形。`thin`（既定。斜めでつながる 1 ドットの線、角が太らない）/ `thick`（上下左右でつながる線、角も埋める） |
| `--outline-colors N` | `darken` で新しく作る輪郭の色の数の上限（既定 4。近い色はまとめる） |
| `--outline-pad` / `--no-outline-pad` | シルエットが画像の端に接しているとき、その辺に 1 ドットの余白を足してから輪郭を付ける（既定で有効）。`--no-outline-pad` では大きさを変えず、はみ出す分は付けない |
| `--palette FILE` | このパレットの色だけで出力する（`.hex` / `.gpl` / `.png`。下記）。別の色だった部品がパレットの同じ色になったら警告する |
| `--save-palette FILE` | 最終結果で使った色（透明は含めない）をパレットファイルに保存する（`.hex` / `.gpl`。拡張子で決める。何度でも指定できる）。入力が複数のときは `<名前>_<出力名>.<拡張子>` |
| `--transparent-ratio R` | 透過画素（α < 128）がこの割合以上のマス（グリッド検出）・ブロック（`mode` / `median` の縮小）を透過にする（既定 0.5） |
| `-o, --output` | `.png` で終わればそのファイル（入力 1 枚のとき）。それ以外はフォルダ（既定 `out/sprite/`、名前は `<入力名>.png`） |
| `--preview-scale N` | 出力をニアレストネイバーで N 倍（1〜32）に拡大したプレビューも `<出力名>_xN.png`（例: `chara64_x4.png`）に保存する。出力そのものは変わらない |
| `--save-steps` | 工程ごとの中間画像を `<出力名>_steps/01_background.png`、`02_grid.png`（または `02_resize.png`）のように保存 |
| `-q, --quiet` | 進捗を表示しない |

### ドット絵風の画像のサイズ指定について

`pixel`（既定）では、出力の大きさはグリッド検出で決まる（1 ドット＝1 画素、キャラクターの大きさに切り詰め）。
`--width` / `--height` / `--scale` や縮小のオプション（`--resize-method` など）を付けると、エラーで止まって理由を表示する
（黙って無視すると、指定どおりの大きさになったと誤解しやすいため）。大きさを変えたいときは次のどれかを使う。

- ドットの大きさが分かっている（推定が外れる）: `--dot-size 20`
- 決まった大きさに縮小したい: `--input-type illust --width 64`
- 見やすく拡大したい: `--preview-scale 10`（出力そのものは 1 ドット＝1 画素のまま）

### グリッド検出（`--input-type pixel`）

AI が描いたドット絵風の画像は、ドット 1 個が約 20px で、場所によって 19〜22px にばらつく。ぼかしの名残で似た色が混ざり、
輪郭には半ドットのずれもある。これを 1 ドット＝1 画素に戻す（`retrocore/sprite/grid.py`）。

1. 隣り合う画素の色の差を、列の境目ごと（行の境目ごと）に足し合わせ、その自己相関の山からドットの大きさを推定する。
   既定ではドットは正方形とみなし、縦横の自己相関を合わせて 1 つの大きさにする（縦横を別々に推定すると、縦横の大きさが
   1 割ほど食い違って出力の縦横比が元の絵とずれることがあった）。`--dot-shape separate` で縦横別
2. 線の間隔を推定値の ±20% に制限し、線の位置での色の差の合計が最大になる並びを **動的計画法** で求める。
   線 1 本ずつではなく全体でいちばんよく合う並びを選ぶので、境目の無い所（同じ色が何マスも続く所）でずれが広がらない
3. 各マスの色: 縁から 2 割より内側の画素を重視して（縁の重み 0.25）、似た色（差 24 以内）が最も多い色を選び、その仲間の平均にする
4. 透明: マスの過半数（`--transparent-ratio`）が透明なら透明。結果は透明か不透明の 2 段階
5. 不透明なマスを囲む長方形に切り詰める

普通のイラストのように格子が見つからないときは、変換せずに理由を表示して止まる（終了コード 1。フォルダ入力では他の画像は続けて処理する）。
推定したドットの大きさ・線の間隔の範囲・出力の大きさ・色数・同じ色が続く行と列の組の数（余分なグリッド線の目安）を進捗に表示する。似た色をまとめる処理は次の工程（単純化）で行うので、
この段階では色数が多い（ai03 で約 600 色）。1254×1254 で 0.5 秒ほど。

比較画像は `python tools/compare_sprite_grid.py 入力.png ...`（既定の出力先 `out/sprite/grid/`）。
ai01〜ai03 の結果は `preview/ai-check` ブランチの `ai-output/grid/`。

```bash
# ドットの大きさを指定（横 20px、縦 18px）
python -m apps.sprite chara.png --dot-size 20x18 -o out/sprite/chara.png

# 等間隔の格子（線を境目に合わせない）
python -m apps.sprite chara.png --dot-size 20 --grid-origin 5,3 -o out/sprite/chara.png
```

### 単純化（似た色をまとめる）

グリッド検出・縮小の後に、似た色を 1 色にまとめて色数を減らす（`retrocore/sprite/simplify.py`）。
ドット絵風の AI 画像はぼかしの名残でグリッド検出の後も数百色ある（ai03 で 617 色）が、本来は 10〜20 色ほどの平塗り。

- ディザは使わない。どの画素も残した色のどれか 1 色になる。透明な画素は色数に数えず、そのまま残す
- 色の近さは **OKLab**（人の目の明るさ・色みの感じ方に近い色空間。色み a・b は 1.5 倍）で測る
- 残す色は元の画像に実際にある色（そのごく近くの色の平均）。たくさん平均しないので濁らない
- ぼかしの名残の色（隣り合う 2 色のちょうど中間の色）は軽く数えて先にまとめ、目・頬・輪郭のような
  面積の小さい色は、周りの色と離れていれば残す（面積で重み付けしない）
- **見分けのつかない色は、色数の上限に関係なく必ず 1 色にまとめる**（距離 `--merge-distance`、既定 0.03 未満）。
  もともと色の少ない画像で、ほとんど同じ色（ai05 の輪郭の紫 4 色など）が上限まで残らないようにするため。
  残す色は、まとめた色の中で最も密な（近くの色のドットが多い）実在の色
  - まずごく近い色をまとめ、それで上限以下になれば終わり（ai05 は 129 色 → 9 色）
  - まだ多ければ、今までと同じ方法で上限まで減らす。まとめて空いた枠があれば、その分だけ別の色を残す。
    ごく近い色が残らない画像（ai03・ai04）では、結果は以前とまったく同じ
- **大きな面の色を守る**（`--keep-large`、既定 0.01）: 面積が全体の 1% 以上の色どうしは、距離 0.06 以上の差があれば、
  ほかにまとめる組が無くなるまでまとめない。淡い色のキャラ（ai07〜ai09: 水色の髪・肌・薄い緑の上着・白）で、
  肌・上着・白が髪の水色にまとめられてキャラ全体が青っぽくなったため（OKLab では淡い肌と淡い水色の距離が 0.064 と小さく、
  何コマも並べた絵では境目の混ざった色（50〜100 ドット）が枠を取っていた）。ai03・ai05 は 12 色・16 色とも結果が変わらず、
  ai04 の 12 色で 31 ドット変わる（肌の明るい所の 6 ドットが中間の茶になる。16 色と同じ色の組み合わせ）。`--keep-large 0` で以前の動き
- 同じ入力からは必ず同じ結果になる（乱数を使わない）。49×45 ドットで 0.05 秒ほど
- `--colors N`（既定 16。PR #39 まで 12）で色数の上限、`--merge-distance D` で「この距離より近い色は必ずまとめる」を指定できる。
  `--merge-distance 0` で以前（上限だけで決める）の動きになる
- **既定の色数を 12 から 16 にした理由**: 淡い色の多いキャラ（ai07〜ai09 の歩き・走り）は 12 色だと上着の薄い緑・肌が髪の水色に寄るため。
  1 枚の絵（ai03〜ai05）では、ai05 は 6 色しか使わず変わらない。ai03 は 57 ドット変わり、かさの右の明るい縁に明るい橙（9 ドット）・
  淡いピンク（6）などの小さな色が増えた（12 色で残っていた暗い赤の 1 ドットは消えた）。ai04 は 35 ドット変わり、ベルトの黄色が 2 色
  （1 色は 2 ドットだけ）に分かれ、濃い緑（7）・眉の上の明るい肌（6）が増えた。どれも「ゴミ」というより細かい陰だが、
  点々が気になる絵は `--colors 12`（画面では色数の欄に 12）にするか、`--cleanup strong` を試す。比較は `preview/ai-check` ブランチの
  `ai-output/web-frames/colors/`

距離の目安（OKLab。色み a・b は 1.5 倍にして測る。明るさだけの差ならそのまま、色みだけの差なら重みなしの 1.5 倍の値になる）:
0.02 でほぼ見分けがつかない、0.05 で並べると分かる、0.1 以上ではっきり違う。既定の 0.03 は、ai03〜ai05 で
見分けのつかない色の組（0.021 以下）をまとめ、残したい色の差（かさの 2 段の赤 0.049、頬と肌 0.054、目と輪郭 0.048 以上）は
まとめない値として決めた（0.025〜0.035 では 3 枚とも同じ結果。0.02 では ai05 の紫が 2 色残り、0.04 では ai03 の 16 色で暗い赤がまとまる）。

`--merge-distance` の意味の変更: 以前は「上限まで減らした後に、この距離より近い色もまとめる」（既定 0 ＝使わない）だった。
今は「上限に関係なく、この距離より近い色をまとめる（まとめて空いた枠は別の色に使う）」で、既定 0.03。
どちらも最後に残る色は「上限以下で、どの 2 色もこの距離以上離れている」ので、大きな値を指定したときの結果は似ている。

```bash
# 16 色に（見分けのつかない色はまとめるので、16 色より少なくなることがある）
python -m apps.sprite chara.png --colors 16 --preview-scale 8 -o out/sprite/chara.png

# 以前の動き（見分けのつかない色もまとめず、上限の 16 色まで残す）
python -m apps.sprite chara.png --colors 16 --merge-distance 0 -o out/sprite/chara.png

# 近さで決める（距離 0.06 未満の色はまとめる。色数は最大 32）
python -m apps.sprite chara.png --colors 32 --merge-distance 0.06 -o out/sprite/chara.png
```

比較画像は `python tools/compare_sprite_simplify.py 入力.png`（既定の出力先 `out/sprite/simplify/`。色数 8・12・16・24）。
ai03 の結果は `preview/ai-check` ブランチの `ai-output/simplify/`。

### クリーンアップ（余計なドットを片付ける）

単純化の後に、ぼかしや半ドットのずれの名残で残った余計なドットを片付ける（`retrocore/sprite/cleanup.py`）。
**新しい色は作らない**。直すときは、そのドットを「まわりにある、すでに使われている色」に置き換えるだけなので、
パレットは増えない（使われなくなった色の分だけ減ることはある）。輪郭を新しく付ける処理（縁取り）はしない。

直すもの:

- (a) **孤立した 1 ドット**（8 近傍に同じ色が無い点）。まわりに溶け込む色（まわりの色に近いか、まわりの 2 色の中間）なら、
  まわりに多い色にする
- (b) **輪郭と面の境目などに細く残る中間色**（まわりの 2 色を結ぶ線分の途中の色で、画像の中でほとんど使われていない色の小さな塊）。
  2 色のうち、まわりに多い色にする
- (d) **輪郭の段の角に余分に付いた 1 ドット**（L 字の角。ダブルコーナー）を内側の塗りの色に
- (c) **部分的に 2 ドットの太さになった輪郭** の内側の列を塗りの色に（`strong` のみ）
- 透明: 外側に浮いた不透明の 1 ドットを透明に、内側の 1 ドットの穴を埋める。それ以外のシルエットは変えない

小さな部品を守る基準:

- 同じ色が 2 ドット以上つながっていれば（斜めも含む）部品とみなし、孤立ドットとしては扱わない（2 ドットの目・頬など）
- 1 ドットでも、まわりのどの色とも離れていて中間の色でもなければ（1 ドットの頬・ハイライト）残す（消すのは `strong` だけ）。
  まわりよりはっきり暗い 1 ドット（1 ドットの目）は `strong` でも残す
- 中間色の片付けは、2 色を結ぶ線分のほぼ上にある色だけ。目（まわりより暗い）・頬（まわりより色みが強い）は対象外。
  広く使われている色（影の面の色など）も対象外
- 輪郭は、直したあとも斜めも含めてつながっているときだけ直す。シルエットの縁の輪郭は変えない

| 強さ | 内容 |
| --- | --- |
| `off` | しない（`--no-cleanup` と同じ） |
| `light` | 溶け込む孤立ドットと、透明の 1 ドット（浮いた点・穴）だけ |
| `normal`（既定） | `light` ＋ 中間色の細い塊（6 ドットまで）＋ 輪郭の角の余分な 1 ドット |
| `strong` | `normal` ＋ 目立つ 1 ドット（頬・ハイライト）も消す ＋ 中間色の塊は 12 ドットまで ＋ 2 ドットの太さの輪郭を 1 ドットに |

同じ入力からは必ず同じ結果になる（乱数を使わない）。49×45 ドットで 0.05 秒ほど。

```bash
# 弱めに（部品をできるだけ残す）
python -m apps.sprite chara.png --colors 12 --cleanup light --preview-scale 8 -o out/sprite/chara.png

# クリーンアップしない（単純化の結果のまま）
python -m apps.sprite chara.png --colors 12 --no-cleanup -o out/sprite/chara.png
```

比較画像は `python tools/compare_sprite_cleanup.py 入力.png`（既定の出力先 `out/sprite/cleanup/`。単純化 12 色・16 色 ×
強さ light・normal・strong。変わったドットに印を付けた画像も並べる）。ai03 の結果は `preview/ai-check` ブランチの `ai-output/cleanup/`。

### 縁取り（外側の輪郭）

クリーンアップの後に、キャラクターの外側の輪郭（シルエットの縁＝透明と不透明の境目）を整える（`retrocore/sprite/outline.py`）。
部品と部品の間の内側の線は扱わない。

| `--outline` | 内容 |
| --- | --- |
| `auto`（既定） | シルエットの縁にすでに暗い輪郭があるかを判定する。あれば新しい輪郭は付けず、輪郭の切れ目（1〜2 ドット）だけを既存の輪郭の色で埋める。無ければ `add` と同じ |
| `add` | シルエットの外側（透明の部分）に 1 ドットの輪郭を付ける。絵の中（不透明なドット）は変えない |
| `thin` | 太すぎる外側の輪郭を減らす。輪郭があれば `auto` と同じく切れ目を埋め、さらに 2 ドットの太さの外側の輪郭を 1 ドットにする（中身を囲む 1 ドットの線は残す。3 ドット以上の暗い面や、明るい色を含まない暗い部品は削らない）。輪郭が無ければ、明るい縁の外側にだけ付ける（すでに暗い縁の外側には付けない）。コマの絵（AI の絵のドット 1 個を 2 ドットに読む絵）で輪郭が太く見えるときに。`--outline-shape thin` とは別の設定 |
| `off` | しない（`--no-outline` と同じ） |

- **「すでに輪郭がある」の判定**: シルエットの縁のドットごとに、内側（透明の反対の向きへ 3 ドットまでと、まわり 8 ドット）にある
  違う色より、OKLab の明るさで 0.1 以上暗ければ「暗い縁」とする（内側も同じ色が続く広い面の端は「暗くない縁」、細すぎる所は数えない）。
  判定できた縁の 6 割以上が暗い縁なら「輪郭がある」
- **切れ目**: 輪郭の線の端から 2〜3 ドット先の別の輪郭までの、間の 1〜2 ドット。シルエットの輪郭につながる線の端だけを対象にし、
  輪郭の線をたどって近くでつながっている（同じ線の曲がり角）所や、間が透明の所は埋めない
- **線の形**: 外側に付けるときは、斜めでつながる 1 ドットの線（角が 2 ドットの太さにならない）。`--outline-shape thick` で上下左右でつながる線
- **余白**: 外側に付けると絵が 1 ドット大きくなるので、シルエットが画像の端に接している辺にだけ 1 ドットの余白を足す。
  足したかどうかは進捗の表示（「余白 上・下 に 1 ドット」「余白なし」）で分かる
- **色**: `darken` は、輪郭のすぐ内側の色を暗くした色（明るさ min(0.18 + 0.25 L, 0.7 L)、色みは 0.8 倍に残す。赤の隣は暗い赤、
  肌の隣は暗い茶色）。近い色はまとめて 4 色（`--outline-colors`）までにし、すでに絵にある色で十分近いものがあればその色を使う。
  増えた色の数は進捗の表示に出る。`single` は 1 色（絵の中でいちばん暗い色。明るすぎるときはそれを暗くした色）か、指定の色

```bash
# 太い外側の輪郭を 1 ドットに（コマの絵でおすすめ。手直しで外側の輪郭を消していた所を自動で）
python -m apps.sprite walk.png --frames --frame-count 3 --outline thin -o out/sprite/walk.png
# 既定（auto）。ドット絵風の入力で輪郭がもともとある場合は、切れ目だけ埋める
python -m apps.sprite chara.png --colors 12 -o out/sprite/chara.png
# 普通のイラストに 1 色の輪郭を付ける
python -m apps.sprite girl.png --input-type illust --height 48 --colors 12 --outline add --outline-color "#3a2030" -o out/sprite/girl.png
```

比較画像は `python tools/compare_sprite_outline.py 入力.png`（既定の出力先 `out/sprite/outline/`。縁取り前・auto・add（darken）・
add（single）と、変わったドットに印を付けた画像を並べる）。ai01〜ai03 の結果は `preview/ai-check` ブランチの `ai-output/outline/`。

### パレット（複数のキャラクターの色をそろえる）

自分のゲームの複数のキャラクターの色をそろえるための機能（`retrocore/sprite/palette.py`）。進め方:

```bash
# 1. 1 体目を変換して、使った色をパレットに保存する（.hex と .gpl の両方）
python -m apps.sprite chara1.png -o out/sprite/chara1.png --save-palette out/sprite/game.hex --save-palette out/sprite/game.gpl
# 2. 2 体目を、そのパレットの色だけで変換する
python -m apps.sprite chara2.png -o out/sprite/chara2.png --palette out/sprite/game.gpl
```

**パレットファイル**（Aseprite・Piskel・LibreSprite などのドット絵エディタでも使える形式）:

| 拡張子 | 読む | 書く | 中身 |
| --- | --- | --- | --- |
| `.hex` | ○ | ○ | 1 行に `RRGGBB` を 1 つ（Lospec などの形式。先頭の `#` は省略可、`;` で始まる行は読み飛ばす） |
| `.gpl` | ○ | ○ | GIMP のパレット（Aseprite も読み書きできる）。Aseprite の `Channels: RGBA` の形式も読める（α は使わない） |
| `.png` | ○ | × | パレットの見本画像。不透明な画素の色を、重複なしで、上から・左からの順に読む（透明は読まない。256 色まで） |

**保存する色の並び順**: 人が見て分かりやすいように、(1) 色みのほとんど無い色（灰色・黒・白）を先頭に暗い → 明るい、
(2) 残りは色み（OKLab の色相）でグループに分け（色相が 25° 以上離れている所で切る。1 つのグループは 90° まで）、
グループは赤 → 橙・肌 → 黄 → 緑 → 水色 → 青 → 紫 → ピンクの順、グループの中は暗い → 明るい。
読み込んだパレットはファイルの順のまま使う。

**`--palette` の動き**:
- 単純化の直後（`--no-simplify` のときはグリッド検出・縮小の直後）に、不透明なドットの色をパレットで最も近い色にする。
  色の近さは単純化と同じ OKLab（色み 1.5 倍）。ディザは使わない。透明は透明のまま（不透明なドットは α を 255 にする）
- そのあとのクリーンアップは、もともと絵の中にある色だけで置き換えるので、パレットの色のまま動く
- 縁取りで外側に輪郭を付けるときは、輪郭の色もパレットの中から選ぶ（内側の色より暗い色の中で、暗くした色に最も近い色。
  `--outline-color` で指定した色もパレットで最も近い色にする）。切れ目を埋めるときはもともとある輪郭の色を使う
- 最後に、パレットにない色が残っていないかを確かめる（進捗の「パレットの確認」。ふつうは 0 ドット）
- **新しい色は足さない**。もとは別の色だった部品が、パレットの同じ色に合わさって消えることがある（頬のピンクと肌が同じ肌色に、など）。
  そのときは警告を表示する（`-q` でも表示する）:

  ```
  警告（chara2.png）: #f7845f（375 ドット） と #ebb39d（170 ドット） が、パレットの同じ色 #fa9a8d になりました
  警告（chara2.png）: #d55e5b（163 ドット）に近い色がパレットにありません。いちばん近い #a45d28 にしました（距離 0.141）
  ```

  色は単純化の後の色（部品の色）。見分けのつかない色（`--merge-distance` 未満）は 1 つの部品として数える。
  「近い色がない」は、パレットの最も近い色との距離が 0.1（はっきり違う色）以上のとき。
  警告が出たら、パレットにその色を足す（.hex なら 1 行足す）か、出力を外部のエディタで直す

**外部のエディタで使うときの注意**（分かる範囲で）:
- Aseprite は `.gpl`・`.hex`・`.png` などのパレットを読める（パレットの「Load Palette」）。RGB の絵のまま使うなら並び順は関係ない
- 絵をインデックスカラーにすると、パレットのどれか 1 つの番号（既定は 0 番）が「透明」の扱いになることがある。
  保存したパレットには透明の色を入れていないので、先頭の色（ふつうはいちばん暗い灰色・黒）が透明扱いにならないか確かめる。
  必要なら、エディタでパレットの先頭に透明用の色を 1 つ足す
- `.hex` は色だけ（名前なし）、`.gpl` は色の名前に `#RRGGBB` を入れている
- Unity・Godot はパレットファイルをそのまま読まない。出力の PNG をそのまま使う（色をそろえるのはこのアプリの側で行う）

### 動き（呼吸・横揺れ・浮遊）

変換が終わったスプライトを材料にして、アニメーションのスプライトシートも書き出す（`retrocore/sprite/motion/`。フェーズ 2。
方針と方法の理由は `docs/sprite-app-plan.md` の「フェーズ 2 の方針」）。変換の結果（`-o` の PNG）は `--motion` を付けても変わらない。

```bash
# 呼吸（2 フレーム、各 500 ミリ秒）。out/sprite/chara_breathe_sheet.png と .json も保存する
python -m apps.sprite chara.png -o out/sprite/chara.png --motion breathe
# 4 フレームで 2 ドットまで下げる（0, 1, 2, 1）。表示時間はフレームごとに
python -m apps.sprite chara.png -o out/sprite/chara.png --motion breathe --motion-frames 4 --breathe-depth 2 --motion-duration 300,200,300,200
# 上下を分ける高さを指定する（出力の画像の下から 12 ドット目のあたり。指定しないか auto なら自動）
python -m apps.sprite chara.png -o out/sprite/chara.png --motion breathe --breathe-split 12
# 横揺れ（4 フレーム、各 300 ミリ秒、中央 → 右 → 中央 → 左）。out/sprite/chara_sway_sheet.png と .json も保存する
python -m apps.sprite chara.png -o out/sprite/chara.png --motion sway
# 下から 10 ドット目のあたりから上を揺らす。8 フレームで揺れ幅 2（0, 1, 2, 1, 0, -1, -2, -1）
python -m apps.sprite chara.png -o out/sprite/chara.png --motion sway --sway-split 10 --motion-frames 8 --sway-amount 2 --motion-duration 150
# 浮遊（4 フレーム、各 400 ミリ秒、中央 → 上 → 中央 → 下。キャラ全体が動く）。out/sprite/chara_float_sheet.png と .json も保存する
python -m apps.sprite chara.png -o out/sprite/chara.png --motion float
# 8 フレームで揺れ幅 2（上下のずれ 0, -1, -2, -1, 0, +1, +2, +1。− が上）
python -m apps.sprite chara.png -o out/sprite/chara.png --motion float --motion-frames 8 --float-amount 2
# 弾む（高さ 2: 0, -1, -2, -1。着地だけ 300 ミリ秒、空中 150 ミリ秒）。out/sprite/chara_bounce_sheet.png と .json も保存する
python -m apps.sprite chara.png -o out/sprite/chara.png --motion bounce
# 高さ 3（0, -1, -2, -3, -2, -1）、全部 120 ミリ秒
python -m apps.sprite chara.png -o out/sprite/chara.png --motion bounce --bounce-height 3 --motion-duration 120
# うなずく（首を自動で探し、首から上が 1 ドット下がって戻る。600・200 ミリ秒）。out/sprite/chara_nod_sheet.png と .json も保存する
python -m apps.sprite chara.png -o out/sprite/chara.png --motion nod
# 下から 16 ドット目のあたりで分け、頭を 2 ドットまで下げる（0, 1, 2, 1）
python -m apps.sprite chara.png -o out/sprite/chara.png --motion nod --nod-split 16 --nod-depth 2
# 伸び（体の上の部分が 1 ドット伸びて戻る。500 ミリ秒ずつ）。out/sprite/chara_stretch_sheet.png と .json も保存する
python -m apps.sprite chara.png -o out/sprite/chara.png --motion stretch
# 2 ドットまで伸ばす（0, +1, +2, +1）。目・頬などの小さな部品の長さは変えない
python -m apps.sprite chara.png -o out/sprite/chara.png --motion stretch --stretch-amount 2 --keep-small-parts
# 見本の表: 弾む（高さ 2）＋着地で 1 ドット縮む・空中で 1 ドット伸びる
python -m apps.sprite chara.png -o out/sprite/chara.png --motion-spec apps/sprite/examples/bounce_stretch.motion.json
```

#### GIF アニメで書き出す（`--gif`）

サイトに載せたり人に見せたりする用に、動きをそのまま見られる GIF も書ける（ゲームにはシートの PNG と JSON を使う）。

```bash
# シートと一緒に out/sprite/chara_breathe.gif（4 倍・透明・ずっと繰り返す）も保存する
python -m apps.sprite chara.png -o out/sprite/chara.png --motion breathe --gif
# 2 倍・背景色あり。動きの表でも使える（out/sprite/chara_bounce_stretch.gif）
python -m apps.sprite chara.png -o out/sprite/chara.png --motion-spec apps/sprite/examples/bounce_stretch.motion.json --gif --gif-scale 2 --gif-background "#203040"
```

- 各フレームはシートのフレームと**同じ絵**（色を変えない・ずらさない）。拡大は `--gif-scale 1〜8`（既定 4）で、ドットをそのまま大きくするだけ
- 背景は `--gif-background`。既定は透明（`transparent`）、`#rrggbb` ならその色で塗る。GIF の透明は「透明か不透明か」の 2 段階
  （変換の結果も 2 段階なので、縁がにじんだりギザギザが増えたりはしない）
- 表示時間はシートの JSON の `duration_ms`。GIF は 10 ミリ秒単位なので、割り切れないときは始まりからの時刻を丸めて合計を保ち、警告を出す
  （125 ミリ秒 × 4 → 130・120・130・120）。20 ミリ秒より短いと、多くのブラウザは 100 ミリ秒として表示する
- 同じ絵のフレームが続くときは 1 枚にまとめて時間を足す（合計は変わらない）。GIF は 256 色（透明のときは 255 色）まで
- 動きを作らなかったとき（`_skipped.json` を書いたとき）は GIF も書かない
- ブラウザ版は動きの欄の「⑥ GIF を保存」。拡大と背景はその下で選ぶ。同じ設定なら CLI と同じファイルになる

- **伸び**（`--motion stretch`）: 体の上の部分が 1 ドット伸びて戻る（呼吸の逆。息を吸う・伸びをする）。足元は動かさない。
  分け目のあたりの継ぎ目のドットを**複製**して、そこから上を 1 ドット上げる（複製するのは元のドットの色なので新しい色は出ない）。
  複製してよい所と決まりは呼吸の抜いてよい所と同じ（1 ドットの横向きの線は使わない・隙間を作らない・輪郭を途切れさせない）
  - `--stretch-amount 1|2`（既定 1）: 1 → 0, +1、2 → 0, +1, +2, +1。フレーム数は量で決まるので `--motion-frames` は使えない。表示時間の既定は 500 ミリ秒（呼吸と同じ）
  - `--stretch-split auto|N|P%`（既定 auto）: auto は呼吸と同じ探し方（腰のあたり）。数・割合は `--nod-split` と同じ書き方。
    その近くで伸ばせなければ付けずに警告し、「近くで分けられる高さ: 8、20」のように作れる高さを出す
  - **余白**: 上に伸びてはみ出す分、上にだけ透明の行を足す（量 2 で最大 2 行。上にもともと透明の行があれば、その分は足さない）。
    JSON の `padding.top` に書く。体全体は動かないので `offset_y` は書かず、`pivot` はフレームの下端（元の足元）のまま
  - 中身は呼吸と同じ列 `upper_y` を + で埋める動きの表。`--write-motion-spec` で書き出し、`--motion-spec` で読み直せる。
    表で縦の変形を + にしても伸ばせる（1 つの列に − と + が混ざってもよい）。表の `"used"` の線は、伸ばす分を `"upper_y+"` に書く
- **小さな部品を守る**（`--keep-small-parts`。呼吸・うなずく・伸びで使える。既定は切）: 縮める・伸ばすときに、目・頬などの小さな部品
  （同じ色が上下左右につながった塊で、縦 3 ドット以下・面積 24 ドット以下）の長さを変えない。継ぎ目は部品を通らず、部品は形のまま上か下に動く。
  表では範囲に `"keep_small_parts": true` と書く。切のときの出力は前の版と同じ。入にすると分けられる高さが減るので、作れない絵もある
  （そのときは近くで分けられる高さを出す）。輪郭と同じ色でつながった大きな目などは「小さな部品」に入らないので守られない

- **うなずく**（`--motion nod`）: 首から上（頭）が 1 ドット下がって戻る。足元も体も動かさない。頭の下げ方と決まりは呼吸と同じ
  （首のあたりの継ぎ目のドットを抜いて上を下げる。新しい色を作らない・隙間を作らない・輪郭を途切れさせない）。中身は呼吸と同じ列
  `upper_y` を埋める動きの表なので、`--write-motion-spec` で書き出して `--motion-spec` で読み直せる
  - `--nod-depth 1|2`（既定 1）: 1 → 0, 1、2 → 0, 1, 2, 1（頭が下がる量）。フレーム数は深さで決まるので `--motion-frames` は使えない
  - 表示時間: 既定は上を向いているコマ 600 ミリ秒、下がったコマ 200 ミリ秒。`--motion-duration 300` のように 1 つだけ書くと全フレーム同じ
  - `--nod-split auto|N|P%`（既定 auto）: auto は首を自動で探す（キャラの高さの下から 20〜85% で、横幅が頭より細くなり、その下で体が広がる行）。
    はっきりしない（スライムのようにくびれが無い・同じくらいの所が 2 つある）ときは付けずに警告し、「試せる高さ: 5、9、13」のように作れる高さを出す。
    首の高さちょうどで作れないときは、上下 2 ドットまでずらして作る（表示に「首を自動で下から 15 ドット目に見つけ、下から 16 ドット目で分けた」）。
    数は下から何ドット目（`--breathe-split` と同じ）、`31.0%` のような割合はキャラの高さに対する下からの割合
  - 自動で首が見つからなかったときは、`--write-motion-spec` の表は書かない（埋める高さが無いため）

- **弾む**（`--motion bounce`）: キャラ全体を分けずに、地面から上にだけ跳ねて戻す（スライム・小動物向け）。浮遊と同じく位置だけを動かし、
  足元も動く（上にだけ。決まりの例外は浮遊と同じ）
  - `--bounce-height 1|2|3`: いちばん上で何ドット浮くか（既定 2）。1 → 0, -1、2 → 0, -1, -2, -1、3 → 0, -1, -2, -3, -2, -1
    （1 フレームに 1 ドットずつ動く）。フレーム数は高さで決まるので `--motion-frames` は使えない
  - 表示時間: 既定は着地（ずれ 0）だけ 300 ミリ秒、空中 150 ミリ秒（地面で一拍止まってから跳ぶ）。`--motion-duration 150` のように 1 つだけ書くと全フレーム同じ、
    `300,150,150,150` のように並べるとフレームごと（数はフレーム数と同じ）
  - **余白**: 上にだけ高さの分の透明の行を足す（`padding` は `{"left": 0, "right": 0, "top": 2, "bottom": 0}`）。下には足さないので
    `pivot` はフレームの下端のまま。`frames[].offset_y` は浮遊と同じ（下向きが +、上が −）
  - `--write-motion-spec` で表（体全体のずれ `root_y` の列だけ）として書き出せ、`--motion-spec` で読み直すと同じファイルになる

- **浮遊**（`--motion float`）: キャラ全体を分けずに、そのまま上下に 1 ドット動かす（幽霊・浮かぶもの・スライム向け）。
  ドットは 1 つも変えず位置だけ動かすので、新しい色・隙間・輪郭の途切れは出ない。**足元も一緒に動く**（今までの動きの決まり
  「足元を動かさない」の例外。動いてよいのは「足元が縦に決まった量だけ動く」ことだけで、横には動かない）
  - `--float-amount 1|2`: 揺れ幅（既定 1）。分ける高さのオプションは無い（`--sway-*`・`--breathe-*` を付けるとエラー）
  - フレーム数は 3〜32（2 では動かない）。揺れ幅 2 は 8 フレームにすると 1 ドットずつ動いてなめらか（4 フレームだと 2 ドットずつ跳ぶ）
  - **余白**: 上下に動いてはみ出す分、上と下に透明の行を足す（揺れ幅 1 なら 1 行ずつ。全フレーム同じ大きさ）。JSON の
    `padding` に `{"left": 0, "right": 0, "top": 1, "bottom": 1}` のように書く
  - **JSON の `frames[].offset_y`**: そのフレームで絵が 1 枚目からどれだけ上下にずれたか（ドット。下向きが +、上が −）。
    `pivot` は 1 枚目の足元（`frame_height − padding.bottom`）。ゲームでは pivot を地面に置けば、1 枚目は元の PNG と同じ位置に立つ。
    影や当たり判定は pivot のまま動かさないか、`offset_y` の分だけ動かして合わせる

- **横揺れ**（`--motion sway`）: 足元は動かさず、体の上の部分が左右に 1 ドットずつ揺れる。各列で「この行から上が揺れる」行を選んで
  つないだ「分け目」から上を横にずらす。分け目は、ずらしても輪郭や 1 ドットの線が途切れない所・目などの小さな部品を割らない所を通り、
  高さを変えるのは横に同じ色が 3 ドット以上続く所の中だけ。新しい色は作らない
  - `--sway-split auto|N`: どの高さから上を揺らすか（数え方は `--breathe-split` と同じ。下から何ドット目のあたりか）。
    近くで形を崩さずに揺らせなければ、**横揺れを付けずに警告**し、近くで分けられる高さを表示する（例: `近くで分けられる高さ: 10、15`）
  - `--sway-amount 1|2`: 揺れ幅（既定 1）。2 は分け目を 2 本使い、上ほど大きく揺れる
  - フレーム数は 3〜32（2 では揺れない）。`--breathe-depth`・`--breathe-split` を付けるとエラー（呼吸のオプション）
  - **余白**: 揺れる部分が画像の左右の端から揺れ幅より近いときは、左右に同じ数の透明の列を足す（全フレーム同じ大きさ。足元は真ん中のまま）。
    そのときシートの 1 フレームは元の PNG より幅が 2（揺れ幅 2 なら 4）ドット広い。足した数は JSON の `padding` に書く
    （`{"left": 1, "right": 1, "top": 0, "bottom": 0}`）。`pivot` は真ん中の下端のままなので、ゲームでは元の PNG と同じ位置に立つ

- **呼吸**: 体の上の部分が 1 ドット下がって戻る。足元（下のほうの行）は動かさない。各列から 1 ドットずつ、目立たない所
  （縦に同じ色が続く所）を選んで抜き、その上を 1 ドット下げる。新しい色は作らない
- 付けられない形（背が 8 ドット未満、横向きの 1 ドットの線が分けたい範囲を横切っている、動かすと部品や輪郭のつながりが変わる）
  では、呼吸を付けずに警告を出す（シートは書かない。変換の結果は保存する）
- **分ける高さ**（`--breathe-split auto|N`）: 自動では、胴に 1 ドットの線（ベルト・ボタン）が多いと首で分かれ、頭だけが動く
  「うなずき」に近くなることがある。胸や腰で分けたいときに数を指定する
  - 数は**出力の画像の下から何ドット目か**（1 = いちばん下の行）。どの数にするかは、目安の画像を作って選ぶと分かりやすい:
    `python tools/compare_sprite_motion.py chara.png --rows`（`out/sprite/motion/chara_rows.png`。左に 5 行ごとの番号。
    灰色の目盛りは足元なので指定できない）。`--split 12 --split 16` のように付けると、高さごとの GIF も作る
  - 上下を分ける継ぎ目は、指定した高さの上下 2 ドット以内を通る。決まり（新しい色を作らない・足元を動かさない・輪郭を途切れさせない など）は
    自動のときと同じ
  - その近くで形を崩さずに分けられないとき（1 ドットの線が横切っている など）は、**呼吸を付けずに警告**し、近くで分けられる高さを表示する
    （例: `近くで分けられる高さ: 13、16`）。その数で試し直す。勝手に別の高さで作ることはしない
  - 画像の高さを超える数はエラー（「画像の範囲の外です。…1〜44 で指定してください」。終了コード 1。変換の結果は保存する）。
    足元の行（下から 12%）を指定したときは、指定できる範囲を添えて警告する
- **シート**: フレームを左から順にすき間なく横 1 列に並べた透明 PNG（拡大しない）。**JSON**: フレームの大きさ（`frame_width`・
  `frame_height`）・枚数（`frame_count`）・各フレームの位置と表示時間（`frames[].x`・`duration_ms`）・足元の位置（`pivot`。
  左上が原点、下向きが +y の画素）
  - Unity: シートを Sprite Mode = Multiple、Slice の Grid By Cell Size で `frame_width` × `frame_height` に切る。
    Pivot は Custom で (pivot.x / frame_width, 1 − pivot.y / frame_height)（下端の中央なら (0.5, 0)）
  - Godot: AnimatedSprite2D の SpriteFrames に「スプライトシートから追加」で横 `frame_count`・縦 1 に切る。
    各フレームの長さは `duration_ms` から決める
- 確認用の画像（拡大した GIF、変わったドットに印を付けたフレームの並び）は `python tools/compare_sprite_motion.py 入力.png`

### 動きの表（`--motion-spec`・`--write-motion-spec`）

動きは「数の表」でも書ける（`retrocore/sprite/motion/spec.py`・`timeline.py`。設計は `docs/sprite-app-plan.md` の
「動きの表（タイムライン）の設計」）。**表の行が 1 フレーム、列が動かし方**で、セルに「そのフレームでどれだけ動かすか」を書く。
今の呼吸・横揺れ・浮遊は「この表を埋めるプリセット」で、中では同じ仕組みでフレームを作る（出力は表の仕組みを入れる前と同じ）。

```bash
# プリセットが埋めた表を書き出す（シートも今までどおり書く）。この表を手で直して --motion-spec で使える
python -m apps.sprite chara.png -o out/sprite/chara.png --motion breathe --breathe-split 12 --write-motion-spec breathe12.motion.json
# 高さを割合（キャラの高さに対する、下からの割合）で書き出す。背の違う別のキャラにも使いやすい
python -m apps.sprite chara.png -o out/sprite/chara.png --motion sway --write-motion-spec sway.motion.json --spec-height percent
# 表で動きを作る。シートは <出力名>_<表の name>_sheet.png / .json（例: out/sprite/chara_bounce_sheet.png）
python -m apps.sprite chara.png -o out/sprite/chara.png --motion-spec tests/motion_specs/bounce.motion.json
```

表の例（弾む相当。体全体が 0 → 1 ドット上 → 2 ドット上 → 1 ドット上。`tests/motion_specs/bounce.motion.json`）:

```json
{
  "format": "sprite-motion",
  "version": 1,
  "name": "bounce",
  "loop": true,
  "tracks": {
    "root_y": {"type": "root", "axis": "y"}
  },
  "frames": [
    {"ms": 150},
    {"ms": 150, "root_y": -1},
    {"ms": 150, "root_y": -2},
    {"ms": 150, "root_y": -1}
  ]
}
```

- **範囲**（`regions`。どこを動かすか）: 3 種類。1 つの表に名前を変えていくつでも書け、列ごとにどの範囲を動かすかを決める
  - **分け目**（`"type": "split"`）: 分け目から上が全部動く。
    `"at"` は `"auto"`（自動）・整数（出力の画像の下から何ドット目。`--breathe-split` と同じ数え方）・`"35.0%"`
    （透明を除いたキャラの高さに対する、キャラのいちばん下の行からの割合）。`"range"` は分け目が at から離れてよい量（省くと 2）
  - **帯**（`"type": "band"`）: `"bottom"`（下の端）〜`"top"`（上の端）の行の間**だけ**が動く。帯の外（上も下も）は 1 ドットも動かない
  - **四角**（`"type": "rect"`）: `"left"`〜`"right"`・`"bottom"`〜`"top"` で囲んだ中**だけ**が動く（例: 剣を持ったキャラの頭だけを囲む）
  - 帯・四角の端は、どれも端の行・列を含む。高さ（`bottom`・`top`）は `at` と同じく下から何ドット目か割合、横（`left`・`right`）は
    画像の左から何ドット目（1 = いちばん左の列）か、透明を除いた**キャラの幅**に対する、キャラの左の端からの割合（`"15%"`）。
    `"range"`（縦の変形の継ぎ目を、範囲の下の端から何ドット以内で選ぶか。省くと 2）・`"keep_small_parts"` も書ける。
    範囲は足元（下から 12%、2 ドット以上）を含められない（含めると作らずに警告し、使える下の端を添える）
- **列**（`tracks`。どう動かすか）: 3 種類。値は −2〜+2 のドット
  | 種類 | 意味 | 値 |
  | --- | --- | --- |
  | `move`（`axis: "x"`） | 範囲を横にずらす（横揺れ）。帯・四角では中身を形のまま横にずらす | + が右 |
  | `move`（`axis: "y"`。帯・四角だけ） | 範囲の中身を形のまま縦にずらす | + が下（`root` と同じ向き） |
  | `deform`（`axis: "y"`） | 範囲を縦に縮める（呼吸）・伸ばす（伸び）。帯・四角では、範囲の下の端の近くの継ぎ目で縮める・伸ばす | − が縮める、+ が伸ばす |
  | `root`（`axis: "y"`。範囲なし） | 絵をまるごと縦にずらす（浮遊） | + が下。**足元が動いてよいのはこの列だけ** |

  頭だけを囲んだ四角でうなずく例（`apps/sprite/examples/head_rect_nod.motion.json`。剣などが首の高さをまたぐキャラ向け）:

  ```json
  "regions": {
    "head": {"type": "rect", "left": "15%", "right": "100%", "bottom": "50%", "top": "100%"}
  },
  "tracks": {
    "head_y": {"type": "deform", "region": "head", "axis": "y"}
  },
  "frames": [{"ms": 600}, {"ms": 200, "head_y": -1}]
  ```

  帯の頭と体全体のずれを一緒に使う例（`apps/sprite/examples/bounce_head_band.motion.json`。着地で頭が縮み、いちばん高い所で頭が伸びる）:
  `"head": {"type": "band", "bottom": "50%", "top": "100%"}` と、`head_y`（変形）・`root_y`（体全体のずれ）の 2 つの列
- **帯・四角の境目**: 範囲の外は動かないので、境目で絵が切れることがある。次のときは作らずに警告し、「近くで作れる範囲」
  （端を 1〜3 ドットずらして実際に作れたもの）を添える
  - 動いた後ろから見えてくる所の色が分からない（範囲の外のすぐ隣が透明か、同じ色の続き（3 ドット以上）なら、その色で埋める。それ以外）
  - 範囲の外に出た所が、外の違う色のドットを隠す
  - 境目で輪郭が途切れる・部品のつながりが変わる・縁に輪郭以外の色が出る（いつもの決まり。帯・四角では輪郭の輪が切れていないかも確かめる）

  ```
  警告（ai04.png）: 2 行目（upper_y = −1、範囲 head）: 1 ドット縮めると輪郭の輪が切れるか、絵の中に隙間ができます。近くで作れる範囲: 下 22〜上 44・左 5〜右 34、下 22〜上 44・左 4〜右 34
  ```
- **行**（`frames`）: 2〜32 行。`"ms"`（表示時間）は必ず書く。書いていない列は 0（動かさない）。表に補間は無い（各行がそのまま 1 フレーム）
- 1 フレームは「ポーズ（位置・変形。足元は動かない）」→「体全体のずれ」の 2 段で作り、それぞれ今の決まり（新しい色を作らない・
  大きさをそろえる・輪郭を途切れさせない・足元は root の分だけ）で確かめる。同じ値のポーズは 1 回だけ作って使い回す
- **作れない行が 1 つでもあれば、シートは書かない**（変換の結果はいつもどおり保存する）。全部の行を確かめて、まとめて警告する。
  行の番号は表と同じ **1 から**（シートの JSON の `index` は今までどおり 0 から）:

  ```
  警告（chara.png）: 動き「broken」のシートを作りませんでした（作れない行が 3 行あります。問題 2 件）
  警告（chara.png）: 2・4 行目（upper_y = −1、範囲 upper）: 下から 3 ドット目では分けられません（足元の 4 行は動かさないため、この絵で指定できるのは 5〜29）
  警告（chara.png）: 3 行目（upper_y = +1、範囲 upper）: 伸ばす（＋）はまだ作れません（今の版で作れるのは縮める − だけです）
  ```
- シートを書かない代わりに、**作らなかった理由の JSON** `<出力名>_<name>_skipped.json` を書く（`-q` でも書く。プリセットの `--motion` でも同じ）。
  中身はシートの JSON と同じ版（2）で `image` は `null`、作ろうとしたフレームの数と表示時間、`skipped`（理由の一覧）。1 件ごとに
  どの工程か（`stage`）・機械で読める名前（`code`。上の警告なら `split_not_found` など）・警告の文（`message`）・フレーム（`frame`。0 から）と
  行（`row`。1 から）・列（`track`）・試した高さや範囲・次に試せる候補（`suggestions`。例 `{"breathe_split": 11}`、表は `{"region": "upper", "at": 11}`）・
  どうしたか（`result`。`held` = 動かさずに元の絵のまま）。code の一覧は `docs/sprite-app-plan.md` の「作らなかった理由の記録（skipped）」
- 作れたシートの JSON にも、いちばん外の最後に `"skipped"` が付く（版 2。何もなければ `[]`。`--palette` の警告はここに `stage: "palette"` で入る）
- 表の書き間違い（知らない列・範囲外の値・version が違うなど）は、変換の前に全部まとめてエラーにする（終了コード 2）。
  シートの JSON をうっかり渡したときは「これは動きの表ではありません」。画像に合わない高さ（画像の外）は「エラー（ファイル名）: …」
- `--write-motion-spec` で書いた表には、作れたとき範囲ごとに**実際に使った高さと線**（`"used"`: `at`・`percent`・`from_bottom`・`lines`）が付く。
  読むときは使わない（目安）。同じ線で作りたいときは、`used` の `lines` を範囲の `"lines"` に写す（継ぎ目・分け目を選ばずにその線を使う。
  決まりの確かめはいつもどおり）
- 帯・四角の範囲の `"used"` は、実際に使った端（数にしたもの。`left`・`right`・`bottom`・`top`）と、縦の変形の継ぎ目（`lines`。範囲の左の列から順の
  「下から何ドット目」）。帯・四角では `"lines"` は書けない（`used` の `lines` は目安）
- `--motion-spec` で作ったシートの JSON は、`at` が `"auto"` か割合の範囲で実際に使った高さと線と、帯・四角で実際に使った範囲を、いちばん外の `"regions_used"` に足す。
  それ以外は `--motion` のシートの JSON と同じ形（`padding` は横の位置・体全体のずれを使ったときだけ、`offset_y` は体全体のずれを使ったときだけ）。
  プリセットの表を書き出して読み直すと、シートの PNG はバイト単位で同じ、JSON も `regions_used` を除いて同じになる
- `--motion-spec` は `--motion`・`--motion-frames`・`--motion-duration`・`--breathe-*`・`--sway-*`・`--float-*`・`--bounce-*`・`--nod-*` と一緒に使えない（表に書く）。
  入力が複数のときの `--write-motion-spec` は `<名前>_<出力の名前>.json`
- 最初の版で作れない組み合わせ（エラー）: 1 つの範囲に同じ行で横の位置と縦の変形（または横と縦の位置）を一緒に書く、
  1 つの行で 2 つの範囲を動かす（体全体のずれ `root` は範囲ではないので、ほかの列と同じ行で使える）、
  分け目の範囲に縦の位置（`move` の `axis: "y"`）、`aim`（自動で狙う高さ。うなずくは首の高さを `at` に数で書くので使わない）
- 画面（ブラウザ版）でも帯・四角を作り・直し・消せる（上の「画面で動かす範囲を作る」。作れないときは「案 1：範囲 head を 下 22〜上 44・左 5〜右 34 にして試す」の
  ボタンと、絵の上の点線の案が出る）

### コマを切り分けてそろえる（`--frames`。歩き・走りなど、何コマも横に並んだ 1 枚の絵）

AI に描かせた歩き・走りのコマ（1 枚の絵に横に並んだもの）を、全部のコマを **1 つのキャラ**として変換し、
同じグリッド・同じパレット・同じ大きさ・同じ足元にそろえて 1 枚のスプライトシートにする。コマごとに別々に変換すると、色・グリッド・位置が
コマごとにずれて、再生したときにちらついたり揺れたりするため。ブラウザ版でも使える（上の「画面でコマが並んだ絵を変換する」）。

```bash
# 横向きの歩き 4 コマ。out/sprite/walk_walk_53x91_4f.png / .json と GIF（4 倍）を書く（53x91 は 1 コマの大きさ、4f はコマの数）
python -m apps.sprite walk.png -o out/sprite/walk.png --frames --frame-count 4 --frame-name walk --gif
# 正面の歩き 3 コマを 1・2・3・2 の順に、150 ミリ秒ずつ。左右反転のシート（_walk_mirror_<幅>x<高さ>_4f.png）も書く
python -m apps.sprite front.png -o out/sprite/front.png --frames --frame-count 3 --frame-order 1,2,3,2 --frame-name walk --mirror
# 走り 4 コマ: 頭の高さでそろえ（空中のコマは足が上がったまま）、100 ミリ秒、体全体を 1 ドットずつ上下させる。ちらつきの画像も書く
python -m apps.sprite run.png -o out/sprite/run.png --frames --frame-count 4 --align-y match --frame-duration 100 --frame-root-y=0,-1,0,-1 --frame-name run --flicker
```

- **切り分け**: 背景を除いたあと、透明な列のすき間でコマを分ける。体から離れた小さな部品（髪の先など。いちばん大きいコマの 15% 未満）は
  列がいちばん近いコマに入れ、ごく小さなもの（0.2% 未満）は背景の消し残しとして使わない。`--frame-count N` を付けると数を確かめ、
  合わなければ**作らずに**警告し、理由を `<出力名>_<名前>_skipped.json`（`code` は `frame_count`）に書く（終了コード 1）
- **グリッド**: ドットの大きさは**全部のコマをまとめて 1 回だけ**推定し、全部のコマで同じ大きさを使う。線の位置（ずれ）は**コマごとに**合わせる
  （AI はコマを別々に描くので、試した絵ではコマごとにずれが横・縦とも 0〜5 画素違った。1 つのずれを全部に当てると、あるコマでは
  線がドットの真ん中を通って色が混ざる）。推定の山が本当の大きさの 2 倍に出たときは、半分の大きさで線がはっきりよく合えばそちらにする
  （表示に「メモ: 推定の山 12.7px は 2 ドット分以上だったので、6.4px にしました」）
  - **線の並びを全部のコマで共通にする**（`--frame-grid`）: コマごとに線を合わせると、ぼかしの具合で狭いマスが入る所がコマごとに違い、
    同じ形に描かれたコマでもドットの数が変わる（ai08 の正面歩き: 元の絵では頭・腕・体の形が 1〜5 画素しか違わないのに 66・68・67 ドットになり、
    腕が 1 ドット左右に揺れた）。`auto`（既定）は、各コマの境目を 1 コマ目に重ねて足し合わせた 1 つの線の並びを作り、どのコマの境目の揃い方も
    コマごとに合わせたときより 0.2 以上は下がらない（基準 0.4 も下回らない）ときだけそれを使う（ai08 は使い、表示に「メモ: コマの形がよく似ているので、
    グリッドの線の並びを全部のコマで共通にしました」。体の動く横向きの ai07・ai09 は使わない）。`each` はいつもコマごと（以前の動き）、
    `shared` はいつも共通
- **パレット**: 全部のコマを 1 枚に並べてまとめて単純化・クリーンアップ・縁取りするので、色は全部のコマで共通。`--palette` で外から渡せる。
  `--save-palette` は全部のコマで使った色を保存する
- **そろえ方**: 全部のコマを同じ大きさのキャンバスに置く
  - 横（`--align`）: `match`（既定。上の方（コマの高さの上から 3 割）の形が 1 コマ目といちばん重なる位置。脚・腕・後ろになびく髪の長さで
    位置がぶれない）、`head`（上の方の不透明なドットの横の中心）、`center`（コマの範囲の中心）、`none`（そろえない）
  - 縦（`--align-y`）: `foot`（既定。足元＝いちばん下の不透明なドットをそろえる。歩きなど足がいつも地面に着いている動き）、
    `match`（上の方の形がいちばん重なる高さ。**走り・跳び**のように足が地面から離れるコマがあるときはこちら。`foot` だと空中のコマが
    足の上がった分だけ沈む）、`none`（元の絵の高さのまま）
- **順番と時間**: `--frame-order 1,2,3,2`（元の絵の左から 1, 2, …。同じコマを何度使ってもよい）、`--frame-duration 150`（既定 150 ミリ秒。
  `150,100,150,100` のようにフレームごとにも書ける）、`--frame-name walk`（ファイル名と JSON の `motion`。既定 `frames`）
- **体全体の上下**（`--frame-root-y`）: フレームごとに体全体を上下にずらす（ドット。− が上。動きの表の `root_y` と同じ）。
  手で描いたコマに重ねると走りが跳ねて見える。− で始まるときは `--frame-root-y=-1,0,-1,0` のように `=` でつなぐ。
  はみ出す分は上下に透明の行を足し、JSON の `padding` とフレームごとの `offset_y` に書く（浮遊・弾むと同じ形）
- **出力**: `<出力名>.png`（そろえたコマを元の順に並べた絵）、`<出力名>_<名前>_<幅>x<高さ>_<N>f.png / .json`（動きのシートと同じ形）。
  **名前の決まり**（PR #39 から。前は `<出力名>_<名前>_sheet.png`）: 幅・高さは 1 フレームの大きさ（ドット。体の上下で足した行も含む）、
  N はシートのフレームの数（`--frame-order` の数）。例 `ai07_walk_53x91_4f.png`。ドット絵のエディタ Piskel の
  「Import as spritesheet」に入れる幅・高さが名前で分かる（CLI も保存のあとに「Piskel で直すときは: … 幅 53・高さ 91」と出す）。
  シートは横 1 列・すき間なし・拡大なしなので、その幅・高さで切ればそのまま元のフレームに戻る（透明だけのフレームは無い。Piskel は透明だけのコマを捨てる）。
  1 枚の絵の動き（呼吸など）のシートの名前は今までどおり `<出力名>_<動き>_sheet.png`（変えると、シートの JSON の `image` が変わり、
  前の版とバイトで同じことを確かめているテスト・作ったファイルの名前に頼る使い方が壊れるため。画面では保存のあとに同じ案内を出す）
  JSON には各フレームの `source_frame`（元の絵の何番目のコマか。1 から）と、いちばん外の `source`
  （`frame_count`・`align`・`align_y`・`mirrored`・`dot_size`）を足した。`pivot.x` はそろえた基準の横の位置（`match` は 1 コマ目の上の方の中心）
  - `--gif`: `<出力名>_<名前>_<幅>x<高さ>_<N>f.gif`（シートと同じ名前。幅・高さは 1 倍の大きさ。`--gif-scale`・`--gif-background` も使える）
  - `--mirror`: 左右反転したシート `<出力名>_<名前>_mirror_<幅>x<高さ>_<N>f.png / .json`（`pivot.x` も反転、`source.mirrored` が true）。`--gif` なら GIF も
- **ちらつきの見える化**（`--flicker`）: 上の方（そろえたキャンバスの上から半分。`--flicker-rows N` で変えられる）で、1 コマ目と違うドットに
  赤紫の枠を付けた画像 `<出力名>_<名前>_flicker.png` と、コマごとの数・場所（64 個まで）の `.json` を書く。各コマは 1 コマ目に
  ±1 ドット横・±2 ドット縦ずらして重ね、いちばん少ないずれで数える（体全体の上下はちらつきと数えない）。**自動では直さない**
  （人がエディタで直すときの目印。数は `--flicker` が無くても表示する）
- **ちらつきを減らす**（`--steady on`、既定 `off`）: そろえた後・シートを書く前に、上の方（既定は高さの半分。`--steady-rows N`）で
  1 コマ目と違うドットのうち、**小さな点**（`--steady-size N` 以下。既定 4）と**短い細い線**（幅か高さが 1 ドットで N の 3 倍まで）だけを
  1 コマ目の色に戻す。体全体の上下は、ずれを戻した位置で比べる。戻さないもの: 大きく形が変わった所（腕・脚・髪の束）とその 2 ドット以内、
  その場所で位置が決まらない所、まわり 2 ドットに戻さない違いがある所（目の半分だけが戻らないように）、目・口などの小さな部品が
  1 コマ目と同じ形にならない所、透明の穴・輪郭の切れ目ができる所、足元が動く所。1 コマ目の色を写すだけなので色は増えない。
  シートの JSON の `steady`（`source` の次）に設定と、コマごとの `restored_dots`（戻した）・`kept_dots`（残した）・`kept_reasons`（理由ごと）を書く
  （off の JSON は前と同じ）。AI が描き直した大きな違い（輪郭が長く 1 ドット隣にある所など）は残るので、最後は Piskel で直す
  （ai07・ai08・ai09 の結果は `docs/TODO.md`）。比較画像は `python tools/compare_sprite_steady.py 入力.png --frame-count 4`
- **1 コマ目と同じにする範囲**（`--same-as-first X,Y,W,H`・`--same-band Y0,Y1`、何回でも。既定は無し＝今までと同じ）:
  AI がコマごとに頭を描き直したちらつき（頭の輪郭・髪の束が 1 ドット隣にずれる）を、人が選んだ範囲ごと 1 コマ目のドットにする。
  範囲はそろえたコマの 1 コマ目の上の座標（左上が 0,0。W・H は幅と高さ、帯は上の行と下の行で両端を含む）。2 コマ目以降で範囲の中身が
  いちばんよく合う位置（上下左右 `--same-search N` ドット以内。既定 3）を探し、そこに 1 コマ目のドットをそのまま写す（頭が揺れていてもその位置に写す）。
  目・口は「1 コマ目とまったく同じ」か「そのコマのまま」のどちらか（範囲ごとに全部写すか何もしないか）。範囲の端から 3 ドット以内では、
  境目が 1 コマ目とそのコマのドットのつながる所を通るように継ぎ目を内側に寄せる。範囲の外から入ってきた太い部品（腕を上げた・髪など）で、
  1 コマ目では透明だった所にあるものは消さずに残す。**写さないもの**（警告と次に試せることを出す）: 合い方 55% 未満（`low_match`）、
  境目で段差・輪郭の途切れ・透明のすき間ができる（`seam`）、穴（`hole`）、足元が動く（`foot`）、入ってきた部品が目・口に触れる・大きすぎる
  （`small_part`・`intrusion`）、キャンバスの外に出る（`edge`）。範囲が足元にかかるときは写せても警告する。
  `--same-from K` で元にするコマを変えられる（既定 1）。`--steady on` と一緒なら、範囲を写した後にちらつきを減らす。
  シートの JSON の `same_as_first`（`source` の次）に範囲・コマごとのずれ・合い方・写した／写さなかった（code）・変えたドット・残したドットを書き、
  写さなかった範囲は `skipped`（`stage: same_as_first`）にも入れる。図 `<出力名>_<名前>_same.png`（緑の枠 = 写した位置、赤 = 写さなかった、
  橙 = 境目の問題、青 = 残した部品）も書く。比較画像は `python tools/compare_sprite_same.py 入力.png --frame-count 4 --range 0,0,53,53`

  ```bash
  python -m apps.sprite 歩き.png --frames --frame-count 4 --same-as-first 0,0,53,53            # 頭（上から 53 行）を 1 コマ目と同じに
  python -m apps.sprite 走り.png --frames --frame-count 4 --align-y match --same-as-first 0,0,62,54 --same-search 4 --steady on
  ```
- **手の直し**（`--edits 直しの一覧.json`。既定は無し＝今までと同じ）: ブラウザ版の「ドットを直す」で保存した `<出力名>_<名前>_edits.json` を、
  1 コマ目と同じにする範囲・ちらつきを減らすの後に当てる。直しは元のコマごとの「ドットの差し替えの一覧」（x, y, パレットの番号か透明）なので、
  1,2,3,2 の 2 と 4 の両方に入る。シート・JSON・GIF・反転・.piskel・`<出力名>.png` に入り、シートの JSON に `edits`（`source` の次。
  `palette`・`dot_count`・元のコマごとの `dots`）を足す。コマの大きさ・コマの数・パレット（直しの色が無い）が合わないときは作らずに理由を表示する。
  直したときと下の色が変わったドット（前の段の設定を変えたとき）は数を警告する。画面と CLI の出力はバイト単位で同じ（`tests/test_sprite_touchup.py`）

  ```bash
  python -m apps.sprite 正面歩き.png --frames --frame-count 3 --frame-order 1,2,3,2 --edits ai08_sprite_frames_edits.json --piskel --gif
  ```
- `--piskel`: シートと同じ名前の `.piskel`（ドット絵エディタ Piskel の Import → Load .piskel file で開ける形。コマ・大きさ・速さが入る）も書く。
  Piskel は速さを 1 つ（1〜24 FPS の整数）しか持てないので、いちばん多い時間から決める（150 ミリ秒 → 7 FPS）。本当の時間は JSON に残る
- JSON のいちばん外の `palette`（PR #40 から）: シートで使った色（`"#rrggbb"`、小さい順）。手直しを読み戻すとき、元のパレットに無い色を見つけるのに使う
- 使えないもの: `--motion`・`--motion-spec`（体全体の上下は `--frame-root-y`）、`--input-type illust`、`--grid-origin`
- 比較画像（元の絵に枠とグリッド、そろえる前と後の GIF、並び、ちらつき）は `python tools/compare_sprite_frames.py 入力.png --frame-count 4`

### 手直ししたシートの読み戻し（`--readback`）

Piskel などで直したシート（PNG か `.piskel`）を入力にして、元の JSON から時間・順番・足元（pivot）・padding・offset_y・source_frame を引き継ぎ、
JSON・GIF・左右反転のシート・横 1 列に並べ直したシート・.piskel を作り直す。**直したドットはそのまま使う**（変換はやり直さない）。

```bash
# 直した .piskel と元の JSON から、<元のシートの名前>_edited.png / .json と確認の画像・記録を out/sprite/ に書く。GIF・左右反転・.piskel も
python -m apps.sprite 直した.piskel --readback walk_walk_53x91_4f.json --gif --mirror --piskel
# Piskel で PNG に書き出した（格子状でもよい）シート。直す前のシートも渡すと、直したドットに印を付けた画像も書く
python -m apps.sprite 書き出した.png --readback walk_walk_53x91_4f.json --original walk_walk_53x91_4f.png -o out/edited
```

- **シートの並び**: 1 コマの大きさ（JSON の `frame_width`・`frame_height`）から読む。横 1 列でなくても（Piskel の書き出しの Columns で格子状）、
  左から右・上から下の順に読む。余ったマスは透明だけのときに限って捨てる。整数倍に拡大して書き出されていても、ドットの形のままなら 1 倍に戻す
- **作らないとき**（理由を表示して終了コード 1）: JSON がシートの情報でない、大きさが 1 コマの大きさで割り切れない、コマの数が JSON と違う、
  透明だけのコマがある（Piskel は透明だけのコマを読み込まないので、コマがずれた可能性が高い）、.piskel の大きさ・コマの数が違う
- **作って警告するもの**（場所は `<…>_edited_check.png` / `.json`）: 元のパレットに無い色（赤紫の枠。元の色は JSON の `palette`、
  無い古い JSON では `--original` のシートの色）、半透明のドット（橙）、同じ元のコマ（`source_frame`）から作ったコマが直したあとで違う（青）
- `--fix-colors`: 元のパレットに無い色をいちばん近い元の色（OKLab）に、半透明を透明か不透明（α 128 が境）に直す（既定は直さない）
- `--same-frames first`: 同じ元のコマを何度も使う順番（1,2,3,2 など）で、後のコマを先に出てくるコマと同じにする（既定 `keep` はそのまま）
- `.piskel` の読み込み: レイヤーが複数あれば、見えるレイヤー（不透明度が 0 より大きい）を下から重ねて 1 枚にする。
  Piskel のプレビューで飛ばす設定のコマもそのまま入れる（警告だけ）。速さ（FPS）は使わず、JSON の時間を使う
- 出力の JSON: 元の JSON の写しで、`image`・各フレームの `x`・`y`（横 1 列）・`palette`（直したシートの色）を変え、いちばん外に
  `edited`（読んだファイル・並び・倍率・新しい色の数・半透明の数・直す前と違うドットの数など）を足す
- `-o` は書くフォルダ（既定 `out/sprite`）。ファイルの名前は元の JSON の `image` に `_edited` を付けたもの（反転は名前の `_mirror` を足すか除く）
- 一緒に使えるのは `--gif`（`--gif-scale`・`--gif-background`）・`--mirror`・`--piskel`・`--original`・`--same-frames`・`--fix-colors`・`-o`・`-q` だけ

### 背景除去

AI 画像のように背景がほぼ単色（少し色むら・ノイズあり）の画像から、背景を透明にする（`retrocore/sprite/background.py`）。

- 背景色: 外周の画素の色を 16 刻みの区間でまとめ、最も多い区間の平均色（`--bg-color` で指定も可）
- 背景色との差（R・G・B の差の最大値）が `--bg-tolerance` 以下で、**外周から上下左右につながっている部分だけ** を透明にする（塗りつぶし）。
  輪郭で囲まれた白い体・白い服は、背景と同じ色でも残る。斜めにはつながらない（1 画素幅の斜めの輪郭から中へ漏れない）
- 結果は透明（RGBA すべて 0）か不透明の 2 段階（半透明は作らない）
- 許容量の既定 32 は ai01〜ai03（`preview/ai-check` ブランチ）で 8〜96 を試して決めた。背景のノイズ（差 4〜6）と輪郭のそばの
  明るいにじみ（差 約 25）を消し、背景に接するクリーム色のドット（差 約 42。40 以上で消える）は残す値
- `--bg-remove-enclosed`: 外周につながっていない背景に近い色の部分のうち、画像の 0.05% 以上の面積のものも消す（小さな部分は目のハイライトとみなして残す）
- 1254×1254 で 0.2 秒ほど
- 縮小（`mode` / `median`）では、透明な画素が `--transparent-ratio`（既定 0.5）以上のマスが透明になる。
  `box` / `bilinear` / `lanczos` で縮小すると、縁に半透明の画素ができる（Pillow の再標本化のため）

比較画像は `python tools/compare_sprite_background.py 入力.png ... --edge-all`（既定の出力先 `out/sprite/bg/`）。
ai01〜ai03 の結果は `preview/ai-check` ブランチの `ai-output/bg/`。

```bash
# 背景色と許容量を指定して、幅 64px に
python -m apps.sprite chara.png --input-type illust --bg-color "#d4f6bd" --bg-tolerance 24 --width 64 -o out/sprite/chara64.png

# 背景除去なし
python -m apps.sprite chara.png --input-type illust --no-background --width 64 -o out/sprite/chara64.png
```

### ドット絵向けの縮小（`--input-type illust` の `mode` / `median`）

出力の 1 画素を入力の長方形ブロック 1 つに対応させ、**ブロック内に実在する色だけ** を採用する
（box などのように平均して新しい色を作らないので、色がにじまず色数も増えない）。

- `mode`: ブロック内で最も多い色。AI 画像は同じ色がほぼ繰り返さないので、各チャンネルを `--mode-bin` の幅でまとめてから数え、
  勝った区間の中で区間の平均色に最も近い実在の色を採用する
- `median`: ブロック内の各チャンネルの中央値に最も近い、実在する色を採用する
- 線優先（`--line-priority`）: 暗い画素（輝度 ≤ `--line-luma`）がブロックの `--line-ratio` 以上なら、暗い画素だけから上の方法で選ぶ。
  細い輪郭線が縮小で途切れないようにするため。透過より優先する
- 透過: 透過画素が `--transparent-ratio` 以上のブロックは透過（α=0）、それ以外は不透明画素だけから選び α=255
- 倍率が整数でないときは、ブロックの境界を `round(i × 入力幅 / 出力幅)` に置く（大きさの差は 1 画素以内で、片側に偏らない）
- 同点は決まった規則で解くので、同じ入力からは必ず同じ結果になる。1024×1024 → 64×64 で 1 秒未満

```bash
# 既定（mode ＋線優先）。4 倍のプレビュー out/sprite/chara64_x4.png も保存
python -m apps.sprite chara.png --input-type illust --width 64 --preview-scale 4 -o out/sprite/chara64.png

# 線優先なし / 従来の nearest
python -m apps.sprite chara.png --input-type illust --width 64 --no-line-priority -o out/sprite/chara64.png
python -m apps.sprite chara.png --input-type illust --width 64 --resize-method nearest -o out/sprite/chara64.png
```

比較画像: [docs/compare/sprite/downscale.png](../../docs/compare/sprite/downscale.png)
（`python tools/compare_sprite_downscale.py` で再生成）。

透過 PNG は透過を保ったまま処理する。透過の無い画像は不透明として扱う。出力は常に RGBA の PNG。

例:

```bash
# 幅 64px（高さは縦横比から）
python -m apps.sprite chara.png --input-type illust --width 64 -o out/sprite/chara64.png

# 手持ちの画像（local_samples/、Git 管理外）をまとめて高さ 64px に
python -m apps.sprite local_samples --input-type illust --height 64 -o out/sprite
```

## 構成

| パス | 内容 |
| --- | --- |
| `apps/sprite/cli.py` | 引数の解析、`build_pipeline()`（工程の組み立て）、入出力 |
| `retrocore/sprite/pipeline.py` | `Step`（工程の基底クラス）と `SpritePipeline`（工程を順に実行） |
| `retrocore/sprite/background.py` | 背景除去 `BackgroundStep`、`remove_background()`、`background_mask()`、`estimate_background()` |
| `retrocore/sprite/grid.py` | グリッド検出 `GridStep`、`grid_to_pixels()`、`detect_grid()`（ドット絵風の入力） |
| `retrocore/sprite/resize.py` | `ResizeStep`（縮小）、`resolve_size()` |
| `retrocore/sprite/downscale.py` | ドット絵向けの縮小 `pixel_downscale()`（mode / median・線優先・透過）、`block_edges()` |
| `retrocore/sprite/simplify.py` | 単純化 `SimplifyStep`、`simplify_colors()`、`merge_close_colors()`（ごく近い色をまとめる。パレット統合からも使う）、`transition_mask()`（中間色の判定）、`rgb_to_oklab()` |
| `retrocore/sprite/cleanup.py` | クリーンアップ `CleanupStep`、`cleanup_sprite()`、強さ `LEVELS`（`CleanupLevel`） |
| `retrocore/sprite/outline.py` | 縁取り `OutlineStep`、`outline_sprite()`、`detect_outline()`（輪郭があるかの判定）、`darken_rgb()` |
| `retrocore/sprite/palette.py` | パレット `PaletteStep`、`match_palette()`（パレットに合わせる・警告）、`load_palette()` / `save_palette()`（.hex・.gpl・.png）、`sort_palette()`（並び順） |
| `retrocore/sprite/image.py` | RGBA 配列（H×W×4, uint8）の読み書き |
| `retrocore/sprite/motion/` | 動き（フェーズ 2）。`make_motion()`、呼吸 `breathe.py`、横揺れ `sway.py`、浮遊 `floating.py`、決まりごとの確かめと共通の設定の確かめ `base.py`（`check_rules()`・`split_limits()`）、シートと JSON の書き出し `sheet.py`（`save_sheet()`） |
| `retrocore/sprite/frames.py` | コマを切り分けてそろえる（`--frames`）。`convert_frames()`（切り分け・全部のコマで同じドットの大きさ・共通のパレット・そろえ方）、`assemble_frames()`（順番・時間・体全体の上下・左右反転）、`flicker_report()`（ちらつきの見える化） |
| `retrocore/sprite/steady.py` | ちらつきを減らす（`--steady on`）。`steady_frames()`（2 コマ目以降の上の方の小さな違いを 1 コマ目の色に戻す）、`steady_image()`（違いの図） |
| `retrocore/sprite/same.py` | 1 コマ目と同じにする範囲（`--same-as-first`）。`same_frames()`（範囲の位置を探して 1 コマ目のドットを写す・境目の確かめ）、`same_image()`（範囲の図） |
| `retrocore/sprite/touchup.py` | 手の直し（`--edits`・画面の「ドットを直す」）。`touchup_from_dict()` / `touchup_json()`（直しの一覧の読み書き）、`apply_touchup()`（当てる・当てられるかの確かめ・下の色が変わったドットを数える）、`touchup_result()` |

画像は工程の間を RGBA の NumPy 配列で受け渡す。工程を足すときは `Step` を継承して `name` と
`apply(rgba) -> rgba`（入力を書き換えず新しい配列を返す）を実装し、`build_pipeline()` に順番どおり追加する。
順番: 背景除去 → グリッド検出（ドット絵風の入力）または縮小（普通のイラスト）→ 単純化 → クリーンアップ → 縁取り → パレット統合
（パレット統合は、パレットファイルの読み書きと指定したパレットに合わせる処理まで。`--palette` のときは単純化の直後に合わせる）。

retrocore の CG 変換（`retrocore/pipeline.py` など）とは独立しており、既存の関数は変更していない。
